# v0.9.0 全栈 demo 试用清单

> 适用版本：v0.9.0（实验性 preview）
> 预计耗时：30–45 分钟
> 这不是生产采用评估；不承诺 full-stack certified 模板。

## 这个 demo 是什么

- `full` profile server + 当前 `jimu-web`，一条命令启动。
- 可体验：平台登录、租户与套餐、用户与角色、账号安全入口。
- 不包含：MFA/Passkey（占位页）、自定义业务模块、`jimu new` 生成的全栈项目。
- 不代表生产可用性、性能、安全或合规结论。

## 试用前检查（维护者）

| 项目 | 要求 | 检查命令 |
|---|---|---|
| Docker | Docker Compose v2 | `docker compose version` |
| Bun | 1.4.x | `bun --version` |
| 基础工具 | `curl`、`openssl` | `command -v curl openssl` |
| 代码 | `jimu` 与 `jimu-web` 同级 checkout | `ls ../jimu-web/package.json` |
| 端口 | 5173/18080/19090/23306/26379 空闲 | 必要时用 `JIMU_DEMO_*` 覆盖 |
| 网络 | 首次构建需拉取镜像和依赖 | 建议提前预热 |

记录本次环境：

```bash
git -C ../jimu rev-parse --short HEAD
git -C ../jimu-web rev-parse --short HEAD
docker compose version
bun --version
```

首次运行通常需要 5–15 分钟构建镜像和安装依赖（本轮本机实测约 2–3 分钟，取决于网络和缓存）；后续运行约 1–2 分钟。

## 路径 A：一条命令起全栈（必做）

1. 在 `jimu` 目录执行 `make demo`。
2. 看到 `Jimu full-stack demo` 横幅后，打开 `http://127.0.0.1:5173`。
3. 使用 `admin` 登录，密码在 `secrets/admin_password.txt`。
4. 按顺序完成并勾选：

- [ ] 租户管理：确认列表出现 `default`；新建一个租户；给它分配套餐；记录套餐名。
- [ ] 角色管理：在刚建的租户下新建一个角色；打开权限抽屉查看。
- [ ] 用户管理：在刚建的租户下新建一个用户；分配刚建的角色；搜索到该用户，角色列显示正确。
- [ ] 账号安全：页面可打开，显示占位说明。
- [ ] 清理：删除用户 → 删除角色 → 删除租户。
- [ ] Ctrl-C 退出，确认 `docker ps` 中没有 `jimu-demo-*` 容器。

## 路径 B：真实后端自动化（可选，维护者执行）

```bash
cd jimu
make demo-e2e
```

期望输出 `3 passed`，结束后没有 `jimu-demo-*` 容器。首次执行前需要：

```bash
cd jimu-web
bunx playwright install chromium
```

## 路径 C：CLI-only 生成项目（可选，偏后端）

```bash
cd jimu
make clean-room-e2e
```

期望输出 `PASS: clean-room basic-api and auth-api`。这条验证的是生成项目，不接前端。

## 请重点观察

1. 从执行命令到登录页，实际耗时和主要等待在哪。
2. 哪一步不知道该点什么、该填什么。
3. 哪些文案或状态容易误解（尤其是套餐、租户、角色范围）。
4. 如果要接入你们现有服务，最大的阻碍是什么。
5. 你们现在的管理端、权限和租户是怎么做的；这个 demo 缺什么、多什么。
6. 是否会推荐给同事，为什么。

- generated full-stack 项目（当前不存在）。
