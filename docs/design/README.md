# 设计文档

本目录记录 Jimu 的稳定设计事实。文档解释职责、协作、流程和约束；具体能力及 profile 清单、配置键、路由和迁移版本应从源码、配置或生成报告读取，不在这里复制易漂移的明细。

## 文档范围

| 文档 | 范围 |
|---|---|
| [能力架构](capability-architecture.md) | 能力如何声明、解析、组合、协作并进入服务生命周期；建议作为架构阅读入口 |
| [身份与租户](identity-and-tenancy.md) | 用户主体、认证凭证、访问控制及租户数据和请求上下文边界 |
| [配置与数据生命周期](configuration-and-data-lifecycle.md) | 配置加载、数据库 schema/迁移、种子、历史数据清理和字段保护 |
| [形态与项目生成](profiles-and-project-generation.md) | profile 构建、运行期筛选和 `jimu new` 生成独立项目的边界 |
| [工程协作工作流](agent-workflows.md) | 仓库规则、Agent skills 与贡献文档的维护关系；这是工程协作设计，不是运行时架构 |

## 文档关系

能力架构定义组合机制。身份与租户、配置与数据生命周期说明具体资源如何落在能力边界内；形态与项目生成说明能力在构建、运行和生成阶段如何被选择；工程协作工作流说明这些设计事实如何被维护和消费。

## 维护规则

- 改变职责边界、数据所有权、组合机制或安全不变量时，同步更新对应设计文档。
- 文档中的流程必须反映当前实现；新增或移除实现路径时，检查文档中的流程图、失败行为和实现映射。
- 文件名使用稳定主题名称，不加日期。方案讨论、阶段计划和历史裁定放在 `docs/superpowers/`，不放在本目录。
- 文档可以链接源码、测试和门禁；不把代码派生的清单、固定数量或报告快照复制成另一份事实源。
- `README.md` 保留用户使用与开发操作说明，并从架构概览链接到本目录。
