# v0.13.1

> 状态：发布候选（2026-11-27）

## 亮点

- Go 工具链从 1.26.11 升级到 1.27.4，仓库、CI、生成模板与文档使用同一版本。

## 变更

- `go.mod` 的 `go` 指令、`.github/actions/go-setup` 的默认版本、`ci-scaffold.yml` /
  `measure-shard-weights.yml` / `release.yml` 的 `GO_VERSION` 统一为 `1.27.4`。
- 仓库 `deploy/docker/Dockerfile` 与生成项目的 `Dockerfile.tmpl` 同步到
  `golang:1.27.4-alpine`，生成项目仍与本仓使用同一 builder 镜像。
- `.golangci.yml` 的 `run.go` 同步为 `1.27.4`，避免 lint 与构建使用不同语言版本。
- `docs/CONTRIBUTING.md` 的最低 Go 版本要求更新为 1.27+。

## 验证

- `go build ./...` 与 `go build -tags jimu_lean ./...`：通过。
- `go vet ./...`：通过。
- `go test ./internal/... ./cmd/... ./tools/... -count=1`：通过（2379 个测试 / 170 packages）。
- `go test ./tools/generator/... -count=1`：通过（488 个测试 / 11 packages）。
- `make check-capabilities`、`make profiles-check`、`make compose-report-check`：通过。
- `make check-templates`、`make test-scaffold-audit`：通过（生成项目 builder 为 `golang:1.27.4-alpine`）。
- `make lint`：0 issues。
- `make govulncheck`：无可达漏洞。

## 说明

- `1.27.4` 修复了标准库 `GO-2026-6859`；升级后不再需要为 Go 1.27.x 单独规避该条目。
- 生成项目的 `go.mod` 的 `go` 指令随框架 `go.mod` 推导，因此新建项目同样使用 1.27.4。
