# v0.12.1

> 状态：发布候选（2026-11-12）

## 亮点

- 修复 v0.12.0 驱动拆分的生成侧缺口：`--db=postgres`、`queue:kafka`、`storage:s3`
  与 `cache:memory` 生成的配置和复制树现在跟随实际选中的驱动。

## 修复

- `auth` 预设的 `--db=postgres` 不再因 `checkcapabilities` 只读取 MySQL 迁移目录而生成失败；
  生成项目只携带所选数据库方言的迁移。
- 生成配置不再把默认值写死为 `mysql` / `redis` / `local`：`db.driver`、`queue.type`、
  `storage.type`、`cache.driver` 会按本次选择重写。
- `--db=postgres` 同步 Helm 的 `db.driver`、`backup.driver` 与 Kubernetes 备份 Job 的
  `DB_DRIVER`，避免部署清单继续使用 MySQL。
- `cache:memory` 会把 `internal/platform/cachemem` 带入复制集，不再因缺少包导致生成失败。
- `access` 的迁移测试允许生成项目只保留一种数据库方言，不再要求 mysql 与 postgres 同时存在。
- Helm 的 `zo_auth_token` 改为在 OTel 或 OTel Collector 任一启用时创建，避免只开
  Collector 时缺少观测凭据。

## 变更

- 生成项目只复制所选数据库方言的迁移目录；默认 MySQL 项目不再携带 postgres 迁移，
  生成文件数相应减少。
- Release workflow 在生成 GitHub Release body 时，会把版本日志的首个状态行自动改写为
  `发布（YYYY-MM-DD）`；仓库文件保留 `发布候选`，发布候选分支无需在打 tag 前手工改状态。
- 统一历史版本日志状态：已发布版本改为 `发布（实际发布日期）`，未创建 tag 的 v0.7.2
  标记为 `未发布`。

## 说明

- 本补丁不改变纯端口能力的预检策略：`--with=cache` 这类没有 HTTP 路由的选择仍要求
  受保护中间件提供方；该行为留到 0.13.0 处理。
- 生成过程中仍可能看到框架自身 full 装配的 Redis 降级告警；它来自生成器进程内的框架
  装配，不影响生成项目已经选中的驱动与配置。
- 本机默认 Go 1.27.3 的 `govulncheck` 会报 stdlib `GO-2026-6859`（1.27.4 修复）；
  上述发布门禁使用仓库 CI 固定的 `GOTOOLCHAIN=go1.26.11`。
