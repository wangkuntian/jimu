# v0.11.0

> 状态：开发中（2026-11-10）

## 亮点

- 内核组件开始按能力集裁剪：0 能力项目的 server 二进制从 52.1 MB 降到 29.5 MB。
- `auth` 的会话、登录失败计数和限流计数器接口化，无 Redis 时自动降级为进程内实现。

## 新增

- `internal/kernel/auth` 新增 `SessionStore`、`FailureStore`、`RateCounter` 三个存储接口与内存实现；
  Redis 实现移到 `internal/kernel/auth/redisstore`。
- `internal/kernel/http/ctxkeys`：HTTP 中间件通过它传递身份，不再直接依赖 auth 服务。
- `internal/kernel/health`：健康检查从 `kernel/observability` 拆出。
- `config.OTELConfig`：OTel 配置类型从 `kernel/observability` 移到 `config`。

## 变更

- `kernel/http` 不再 import `auth`、`redis`、`tenant`：身份中间件拆到
  `kernel/http/middleware/{ratelimit,idempotency,bodywriter}`。
- `contract` 与 `config` 不再依赖任何内核实现包。
- `kernel/auth` 零 Redis 依赖；无 Redis 时使用内存存储，多实例部署下会话与限流只在单实例内生效。
- 0 能力项目不编译 OTel 初始化（`internal/app/bootstrap_otel.go` 按闭包裁剪）。
- 未启用 `access` 时不编译 Casbin 种子同步（`internal/app/seed_casbin.go` 按能力集裁剪）。
- 生成器的裁剪点改为在闭包计算前用 `go/packages` overlay 隐藏可选文件，不再先算全量闭包再删文件。
- 未启用 `access` 的生成项目不再夹带 `internal/kernel/access`（此前会复制进来但从不编译）。
- 新增 `jimu new --db=mysql|postgres`（默认 `mysql`）：只编译所选数据库驱动与其方言的迁移。
  默认 MySQL 项目不再带 gorm postgres driver 与 pgx（约 3.6 MB）。
- 新增 `internal/kernel/lock`：调度器改依赖 `Locker` 接口，不再 import `kernel/redis`。
- 0 能力项目不再编译 Redis：`container`/`bootstrap`/`assembly` 的 Redis 装配改为 build tag
  二选一（`!jimu_noredis` / `jimu_noredis`），生成器只保留空实现那一份并去掉 tag。
  go-redis 及其限流/幂等中间件不再进入产物（约 5.7 MB）。
- `docs/templates/v1/budgets.json` 的 `auth`/`full` 闭包预算各上调 4/2 个文件，用于新增的接口与内存实现。
- `docs/templates/v1/budgets.json` 的 `auth`/`full` 闭包文件预算各再上调 1 个（`seed_casbin.go`）。

## 说明

- 本轮只完成内核解耦的前半部分。`assembly.Context` 仍以具体类型暴露 Redis、EventBus、
  HTTPClient、Scheduler、Reporter，剩余体积优化留到后续版本。
