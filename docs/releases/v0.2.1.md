# v0.2.1

> 状态：未发布 — 正在 `release/v0.2.1` 集成（依赖更新与安全修复），发布时移除本说明并补充发布日期的验证结果。

## 亮点

维护性补丁版本：合并 6 项依赖升级，并为 excelize 的解析 panic 增加兜底与门禁豁免说明。

## 变更

- 合并 6 个 Dependabot 依赖升级 PR：`github.com/fsnotify/fsnotify` v1.10.1、`github.com/aws/aws-sdk-go-v2` v1.45.1、`github.com/aws/aws-sdk-go-v2/config` v1.33.1、`github.com/aws/aws-sdk-go-v2/service/s3` v1.109.1、`modernc.org/sqlite` v1.57.0、`go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc` v1.46.0

## 修复

- **Excel 导入解析兜底** — `internal/platform/importer` 的 `Parse` 现在对 excelize 解析异常（含 GO-2026-6452 的负共享字符串索引 panic）做 `recover` 兜底：构造过的上传文件只会返回错误，不会打挂请求或后台任务 goroutine
- **govulncheck 门禁豁免机制** — 新增 `scripts/govulncheck.sh`：默认对所有可达漏洞失败，仅豁免清单内的 ID（当前仅 `GO-2026-6452`，因上游尚未发布修复版本且代码侧已兜底）；`make govulncheck` 与 CI 均改走该脚本，消除"本地与 CI 不一致"
- **集成测试并发迁移竞态** — `internal/shared/testutil` 的 `Migrate()` 现在用数据库级咨询锁（MySQL `GET_LOCK` / PostgreSQL `pg_advisory_lock`，固定在同一连接上）串行化迁移：`go test` 并行跑多个包共用同一测试库时，不会再出现两个进程同时执行迁移 DDL 导致 `Error 1060 Duplicate column name 'tenant_id'` 之类的随机失败；新增并发迁移用例，无锁时在全新库上必失败、加锁后稳定通过
