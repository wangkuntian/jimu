# v0.3.2

> 状态：本地实施与门禁通过；待 PR CI 和发布。

## 亮点

- 统一能力骨架入口为 `jimu capability create <name>`，移除旧 `jimu module create`。
- 以根包 `Descriptor`/`Wire` 定义能力目录契约，按职责建立分层目录。
- 将跨能力调用收敛至 `internal/contract` 端口，能力内部禁止直接 import 其他能力。

## 变更

- `capability create` 生成可装配的典型 CRUD 能力，包含自有表声明与 `Wire`；不自动改 catalog/profile。`capability add` 仍向已生成项目追加已有能力。
- `check-capabilities` 静态检查能力入口及跨能力 import，覆盖能力测试和驱动子包；`catalog` 为组合根例外。
- 保持租户开通、OAuth 首次登录的原子事务语义，以及 outbox 的 MQ 延迟初始化。

## 验证

- `go test ./... -count=1`、`make fmt-check`、`make vet`、`make lint`、`git diff --check` 通过。
- `make check-capabilities`（6 条）、`make profiles-check`（5 个形态构建及 golden 闭包）、`make compose-report-check`、`make check-skills`、`make check-templates` 和 `make test-scaffold-matrix` 通过。
- `jimu capability create --help` 正常；旧 `jimu module create` 返回 unknown command。租户开通与 OAuth 首次登录的回滚测试通过。

## 说明

- 旧命令没有兼容别名；既有自动化需要改用 `jimu capability create`。
- 五个形态的启动与健康检查需要 DB/Redis，本地未设置 `JIMU_PROFILES_SMOKE=1`，因此没有执行该部分；远端 PR CI 尚未运行。
