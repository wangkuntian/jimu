# v0.8.0

> 状态：发布（2026-11-05）

## 亮点

- 生成项目获得统一的只读生命周期检查、可操作的 deep 验证和可稳定解析的升级诊断。
- 建立首版本地实验基线，让生成、健康检查、fast/deep 诊断和 upgrade 诊断可以用同一口径重复比较。

## 新增

- `jimu check` 检查受管文件漂移、当前与目标版本、升级可用性、待处理 conflict 和下一步命令。
- `jimu check --deep` 在临时项目副本中串行执行配置校验、`go build ./...` 和 `go test ./...`。
- `jimu check --json` 输出 schema version 1 的确定性生命周期结果。
- `jimu upgrade --json` 输出 schema `v1`、分类计数、存在状态、SHA-256 和下一步动作。
- `jimu upgrade --diff` 输出 local 到 target 的统一 diff；二进制或非法 UTF-8 文件只报告元数据。
- 本地实验采集入口 `scripts/experiment_v0_8_0.py` 与 v0.8.0 基线。

## 变更

- 受管文件漂移、可用升级和 conflict 只产生 warning；非法 manifest/组合与 deep 失败退出非 0。
- `--json`、`--diff` 只允许和 `upgrade --dry-run`/`--check` 组合，实际升级会拒绝诊断 flags。
- fast/deep 检查均保持用户项目文件不变；deep 不在项目中运行 Make 或业务脚本。
- 本地实验默认不上传，不采集业务数据或真实项目标识。

- 数据库 schema 仍不进入 `jimu upgrade` 自动迁移范围。
