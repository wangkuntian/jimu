# v0.12.0

> 状态：发布（2026-11-11）

## 亮点

- kernel 包开始按「能力 = 功能，驱动 = 实现」拆分：缓存从内核组件变成可替换驱动的能力，
  `cache:redis` 与 `cache:memory` 二选一，0 依赖项目也能用上缓存。

## 新增

- `internal/capabilities/cache`：缓存能力。接口层只声明语义（Get/Set/Delete/DeletePattern/
  Exists/GetOrSet/Close），实现由驱动在 `init()` 中注册。
- `internal/capabilities/cache/redis`：Redis 驱动，保留原有的进程内 singleflight 与
  Redis 分布式锁两级防击穿。
- `internal/capabilities/cache/memory`：进程内驱动，单实例语义，不需要任何外部服务。
- `internal/capabilities/auth/authstore`：auth 的会话、限流、失败计数与重置码存储契约。
- `internal/capabilities/auth/redis`、`auth/memory`：两种 auth 存储驱动。

## 变更

- `internal/kernel/cache` 删除，等价实现迁入 `internal/capabilities/cache` 及其驱动。
- `cache` 从内核配置段变成能力配置段：未选择 `cache` 的项目不再生成 `cache:` 段，
  Helm `values.yaml` 的 `cache` 键也随之裁掉。
- `cache.driver` 缺省为 `memory`；`cache.prefix` 缺省为 `cache`。
- `auth` 的会话、限流、失败计数和密码重置码改为驱动：`redis`（默认）与 `memory`。
  `auth:memory` 项目不依赖 Redis；选 Redis 但客户端不可用时启动告警并降级到内存。
- `search` 的 MySQL FULLTEXT 与 PostgreSQL tsvector 实现拆成 `mysql` / `postgres` 驱动，
  生成器按 `--db` 自动选择，不再同时编入另一种方言。
- `jimu capability add <name> --driver=<name>` 可在追加能力时选择非默认驱动；未知驱动
  直接报错并列出该能力的可用驱动。
- `internal/kernel/auth` → `internal/platform/identity`，`internal/kernel/access` →
  `internal/platform/authz`。这两个包被 6 个能力当作共享基建使用，不满足「能力之间禁止
  互相 import」，因此归入 platform 层而不是某个能力。
- `internal/kernel` 目录整体退役：其余 db、http、logger、scheduler、event、metrics、
  reporter、tenant、seedmodel 等基础包统一迁入 `internal/platform`，能力与生成器不再引用
  已不存在的 `internal/kernel` 路径。
- `full` 形态支持 24 个能力；预算上调至生成文件 820、闭包文件 374、闭包行数 40400。

## 说明

- `minimal` 仍为 0 能力，不包含 `cache`：缓存是功能能力，0 能力起点不该默认带上。
- `cache` 只提供端口、没有 HTTP 路由，因此 `--with cache` 单能力组合会因
  「有受保护路由但无中间件提供者」被预检拒绝——这与 `storage`/`encryption`/`queue`
  等纯端口能力的既有行为一致，不是本次引入。
