# v0.7.2

> 状态：发布候选（2026-11-04）

## 亮点

- 提供未来真实项目跨版本升级验证的本地证据规范，明确三项项目覆盖、冲突、耗时、回滚和隐私边界。

## 新增

- `docs/UPGRADE-VALIDATION.md`：upgrade validation project 的资格、采集流程、匿名摘要模板和关闭条件。
- [ADR 0004](../adr/0004-real-project-upgrade-evidence.md)：fixture 不作为真实项目证据，内部匿名证据与公开案例分离。
- 术语表补充 upgrade validation project、upgrade evidence record、design partner 和 local metric collection。

## 变更

- 未来恢复真实项目验证时，验收口径为 3 个项目分别覆盖 HTTP/BFF、数据库加认证、队列/异步任务。
- 每个项目从已发布起始版本升级到目标版本，至少一个项目从 `v0.7.1` 之前开始。
- 回滚次数统一定义为升级事务自动回滚与升级后人工恢复次数之和。

## 验证

- `make release-check`：**通过**。覆盖 `fmt-check`、`vet`、`check-log-usage`、`check-capabilities`、`profiles-check`、`compose-report-check`、`check-makefile`、`check-config`、`bundle-check`、`go test ./...`、`govulncheck`、`compose-check` 与完整 `test-scaffold-matrix`。

## 说明

- 当前 v0.8.0 路线不包含真实项目验证；本版本保留证据规范作为未来工具，不把 fixture 计为真实验证。
- P2-01、P2-02、P2-03 和 F-01 不在本版本范围。
- 本版本不新增 `jimu upgrade` 参数；指标与证据继续采用本地、显式采集，默认不上传。
- `basic-api` / `auth-api` 保持 certified；`--with` 和 `capability add` 仍为 experimental，不承诺组合级升级兼容。
