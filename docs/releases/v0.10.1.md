# v0.10.1

> 状态：发布（2026-11-09）

## 亮点

- 生成项目瘦身：编译默认剥离符号表，minimal 服务端二进制 78.4 MB → 52.1 MB。
- 生成项目不再携带多形态资产工具：`tools/profileoverlay`、`tools/profileassets`、
  `tools/composereport` 及其内部库从产物中移除（约 1400 行框架专用代码）。
- 生成项目的项目标识统一跟随目录名，不再残留框架名。

## 修复

- `make build-server` / `make build-cli` 的 `LDFLAGS` 补上 `-w -s`。Dockerfile 早已带这两个参数，
  Makefile 之前漏了，导致本地构建的二进制比镜像里的大 26 MB。
- 镜像仓库名、镜像内 CLI 产物名不再固定为 `jimu`：生成 `myapp` 时得到 `IMAGE_REPO ?= myapp`
  与 `/app/myapp`。此前 Makefile 的二进制名会按项目名改写、镜像名不会，两者不一致。
- k8s 资源名、namespace、`app` 标签、secret/config 名、Helm `Chart.yaml` 的 `name` 与
  `values.yaml` 的 `repository`/`prefix`/`serviceName`/数据库用户名跟随项目名。
- CLI 的 `Use` 与 `Short` 跟随项目名，不再自称 `jimu`。

## 变更

- 生成的 Makefile 移除 `profiles-check` 与 `compose-report` 两个目标。
  它们依赖的目标工具已不再随生成项目发布；单形态项目也没有可供 overlay/比对的第二个形态。
- 生成项目不再产出 `scripts/check_profiles.sh`。
- `tools/checkcapabilities` 的形态闭包 overlay 改为内联生成，不再依赖 `tools/internal/profileoverlay`。
  框架仓仍是多形态，门禁照常按形态替换 `internal/profiles/active`；生成项目只有一个形态，结果不变。

## 不兼容变更

- 由旧版本生成的项目若仍引用 `make profiles-check` / `make compose-report` / `scripts/check_profiles.sh`，
  升级生成器后重新生成才会消失。已有生成项目不受影响，可继续使用原有脚本。
- 生成项目的部署清单里，OpenObserve 资产与告警规则的 `jimu_` 前缀保持不变：它们是运行期协议名
  （指标名、日志/trace stream、告警规则），改名会断开既有仪表盘。只有 namespace、资源名与镜像名跟随项目名。

## 验证

- `go build ./...` / `go vet ./...`：通过。
- `go test ./tools/...`：通过。
- 实测生成 `minimal` 项目：`go build ./...`、`go test ./...`、`go run ./tools/checkcapabilities` 全绿；
  `make build` 产出 `bin/<name>-server`（52.1 MB）与 `bin/<name>-cli`（40.2 MB）。
- 生成物文件数 295 → 290。

## 说明

- 内核闭包仍包含 DB/Redis/Casbin/迁移驱动（0 能力项目 44 个直接依赖）。这是「最小内核」的既定边界，
  进一步拆分需要改 `internal/app/container.go` 的条件装配，属于独立任务。
- `tools/checkcapabilities` 与 `tools/logcheck` 保留：它们对生成项目仍有实际门禁价值。
