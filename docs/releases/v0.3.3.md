# v0.3.3

> 状态：release 分支本地实施中，待发布候选 PR 与远端验证。

## 亮点

- 生成器改为由确定性 JSON manifest 驱动，框架内部能力、形态和 contract 元数据通过适配层导出，生成器核心按动作计划执行。

## 新增

- 生成项目保存 `.jimu/manifest.json`，包含能力选择、驱动、复制/模板/合并/重写/资产动作、裁剪规则、报告事实、生成文件清单和 digest。
- `make check-capabilities` 增加生成器核心边界门禁，确保核心子包不直接读取 `internal/capabilities`、`internal/profiles` 或 `internal/contract`。
- `tools/generator` 按 manifest、frameworkmanifest、plan、render、workspace、report 等职责分目录。

## 变更

- `jimu new` 与 `jimu capability add` 共用 manifest pipeline，报告度量改用框架无关的 `ReportSpec`。
- manifest 只支持 JSON，路径必须是仓库相对路径；v0.3.2 的 `.jimu-generated` 不迁移也不兼容，旧生成项目需要重新执行 `jimu new`。

## 验证

- `go test ./tools/checkcapabilities -count=1` 通过。
- `go test ./cmd/cli ./tools/generator/... ./tools/composereport -count=1` 通过。
- `git diff --check` 与 `make check-skills` 在发布前复核；完整 `make release-check COMPOSE_ENV=.env.example` 由发布候选验证阶段执行。

## 说明

- 本版本不拆分独立脚手架仓库或发布物，不提供 YAML/TOML manifest 输入，也不提供跨版本生成项目升级命令。
