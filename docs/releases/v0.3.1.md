# v0.3.1

> 状态：发布流程演练分支 `release/v0.3.1`。

## 亮点

- 减少 release 分支合并与 tag 发布阶段的重复 CI。
- 把重型 Scaffold Matrix 集中到 `release/* → master` 发布候选 PR。

## 变更

- 常规 Go、Docker 和提交消息 workflow 只响应 PR 与手动触发，不再因 master/release/* 的 branch push 重复运行。
- Scaffold Matrix 保留手动触发和每周定时，仅在 release/* → master 发布候选 PR 自动运行。
- tag workflow 校验 tag 指向当前 master tip 后，直接构建四个平台二进制并创建 GitHub Release，不重复运行完整测试、镜像扫描或 Scaffold Matrix。
- master 与 release/* 的 GitHub ruleset required checks 作为合并前门禁；release/* → master 额外要求 Scaffold Matrix，其它来源分支向 master 直接提 PR 会在该检查中失败。

## 验证

- `actionlint` 通过；5 个 workflow 均可由 YAML 解析器读取。
- 触发契约静态检查通过：常规 workflow 无 branch push 触发，Scaffold Matrix 只响应 release/* → master PR/手动/定时，tag workflow 只有发布 job。
- `make check-capabilities`、`make profiles-check`、`make compose-report-check` 通过；tag-tip 校验算法在当前 master tip 上模拟通过。
- `make release-check COMPOSE_ENV=.env.example`：待发布候选 PR 在远端运行；本地未重复执行约 15 分钟的 Scaffold Matrix。

## 说明

- GitHub Actions 的实际 PR、合并和 tag 运行需要推送分支并创建 Pull Request；本地演练只验证工作流结构、分支规则配置和 tag-tip 校验逻辑。
- 生成器仍保留在本仓库；本次只调整 CI 触发与发布编排。
