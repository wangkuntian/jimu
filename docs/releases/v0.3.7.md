# v0.3.7

> **发布口径**：本项改动随 `master` 进入**下一个版本**；是否打 tag 由维护者决定（v0.3.6 已发布且保持不变）。

## 亮点

- **移除「攒批依赖分支」`dependency-updates`，依赖升级改走 master 主线**：dependabot 的 PR 直接面向 `master`，与发布候选 PR 过同一套门禁。机制少一整套（常驻分支 + 它的 ruleset + 单向上游同步），依赖升级的验证时机也从「发布时」提前到「PR 当场」。

## 变更

- **dependabot 直接面向 `master`**：`.github/dependabot.yml` 四个生态（`gomod`/`github-actions`/`docker`/`docker-compose`）去掉 `target-branch: "dependency-updates"`，改为面向默认分支；分组、排期（周一 02:00/02:30/03:00/03:30，`Asia/Shanghai`）与开 PR 限额（10/5/5/5）全部不变。minor/patch 仍由 `.github/workflows/dependabot-auto-merge.yml` 自动合并，major 留人工评估。
- **依赖 PR 与发布候选 PR 走同一套 master 门禁**（`PR Gate`/`Image Gate`/`Scaffold Gate`）：依赖升级会在**脚手架矩阵里当场验证**，而不是攒到发布候选 PR 才第一次跑 —— 代价是依赖 PR 也要等完整门禁，收益是「晚发现」变成「不发现」。
- **`Start Release Branch` 总是从 `master` 切出 `release/<version>`**：`.github/workflows/start-release.yml` 删除 `source` 输入（不再有选错起点分支的空间），checkout `ref` 固定为 `master`；版本号格式校验与「`release/<version>` 已存在则拒绝」保留。

## 移除

- 常驻分支 `dependency-updates` 及其 ruleset（v0.3.5 引入）。删除是干净的：没有未合并的依赖 PR 指向该分支。

## 验证

- `actionlint` 无输出、exit 0；两个 workflow 与 `.github/dependabot.yml` 的 `yaml.safe_load` 通过。
- `grep -rn "dependency-updates" .github/ docs/CONTRIBUTING.md` 只剩历史说明与流程引用，不含 `target-branch` 与 `source` 默认值（逐条解释见本版本 PR 描述）。
- 本 PR（`release/v0.3.7` → `master`）的 `PR Gate` / `Image Gate` / `Scaffold Gate` 结论见 PR 检查。

## 说明

**发布口径**：v0.3.6 已发布（tag 与 8 个产物保持不变，不重切、不补发），因此本版本的改动**随 `master` 进入下一个版本**，本次不打任何 tag；是否把本文件对应的版本打上 `v0.3.7` tag 由维护者决定。本文件因此是「下一个版本的累积日志」，版本号沿用下一版的自然编号。

**为什么移除（该分支连锁引出的四个问题）**

1. 该分支必须 require `PR Gate`（这是 `dependabot-auto-merge.yml` 的 `--auto` 不能抢跑的前提）⇒ 而 GitHub 的 `required_status_checks` **同时拦截直推**。
2. 直推送不进去，master → 该分支的同步就只能走 PR。
3. 走 PR 又撞上两条 GitHub 限制：`GITHUB_TOKEN` 默认不允许创建 PR；即使打开开关，用它创建的 PR 也不会触发工作流（运行停在 `action_required`）⇒ 自动化无解，v0.3.6 因此删掉了 `sync-dependency-branch.yml`。
4. `Start Release Branch` 从该分支切出会**漏掉 master 的提交**（v0.3.6 发布时额外做了一次反向合并才绕开）。

**发布前置条件（不在本次改动范围内）**

- `.github/workflows/ci-scaffold.yml` 目前只接受 `release/*` 来源的 master PR：shards job 的 `startsWith(github.head_ref, 'release/')` 守卫与聚合 job 的 `RELEASE_SOURCE != release/*` 判定，会让 dependabot 来源的 PR 在 `Scaffold Gate` 上**红且不可合并**（master ruleset 无 bypass actor）。**必须同时放行 dependabot 来源**，依赖 PR 才真的跑脚手架矩阵。
- `.github/workflows/dependabot-auto-merge.yml` 仍绑定 `branches: [dependency-updates]` 与 `base.ref == 'dependency-updates'`，需一并改为 `master`，否则 minor/patch 不再自动合并。
- `.github/workflows/ci.yml` 的 `on.pull_request.branches` 仍列着 `dependency-updates`（无害的死条目），可顺手清掉。
