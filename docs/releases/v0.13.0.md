# v0.13.0

> 状态：开发中（2026-11-12）

## 亮点

- 继续精简 `minimal` 生成项目：按运行时闭包裁剪源码、测试和工具，并移除没有消费者的
  编译面度量工具。

## 变更

- 生成项目不再复制 `tools/internal/projectmetrics`。该包仍保留在框架仓，供
  `jimu new --report` 与 `tools/composereport` 使用。
- `minimal` 生成项目减少 2 个 Go 文件、约 263 行框架侧代码。
- `jimu new` 新增 `--tests=selected|all|none` 与 `--tools=auto|all|none`。
  `minimal` 默认 `selected` + `auto`，`auth`/`full` 默认保留全部工具。
- `jimu new` 新增 `--deploy=compose,k8s,helm,observability|all|none`。`minimal` 默认
  `none`，`auth` 默认 `compose`，`full`/`--with` 默认 `all`；MySQL 能力自动派生备份资产。
- 部署资产统一收敛到 `deploy/`：`docker/`、`compose/`、`k8s/`、`helm/`、
  `observability/`、`backup/`、`scripts/`。生成项目按组件渲染 Dockerfile/compose，
  Makefile 的 `up`/`down`/`logs`/`status` 与 `up-observability` 也按组件出现。
- 新增 manifest schema v4 的 `generation` 字段，持久化运行时闭包、测试模式、工具模式与
  解析结果、部署组件、CLI 命令集和 CLI 交互形态。
- 生成和升级先在暂存树内做容错 tidy，再按 `cmd/server`、`cmd/cli` 与显式工具入口计算
  多平台 package 闭包；不可达 package、测试文件和工具随后删除。
- `tools=none` 不生成工具目录及 Makefile 对应目标。`--no-tidy` 只跳过最终 tidy，
  内部 tidy、闭包裁剪、构建和门禁仍执行。
- `capability add` 保留既有测试/部署/CLI 策略，只按新能力集重算 `tools_resolved`；
  `upgrade` 原样携带 generation，v3 项目使用保守默认，不启用 Compose 或 TUI，也不移动
  旧部署文件。
