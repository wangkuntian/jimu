# v0.3.5

## 亮点

- 依赖更新纳入自动化发布周期，最终发布候选仍由维护者审核。

## 变更

- 仓库 owner/member/collaborator 创建 Release Issue 后，自动创建版本 release 分支和固定 Dependabot 汇总分支；普通版本更新经过 focused checks 后自动 squash merge。
- 依赖收集满 8 天并安静 24 小时后自动创建汇总 PR；`CI (Go)`、`CI (Docker)`、`CI (Commits)` 完成并通过后自动合并到 release 分支，再创建 `release/vX.Y.Z -> master` 候选 PR。
- 目标为 `master` 的 Dependabot 安全更新继续运行 CI；Scaffold Matrix 返回成功 skip，并记录到活跃 Release Issue。
- 最终候选 PR 合并后自动创建版本 tag；现有 Release workflow 发布成功后更新 Release Issue 状态。
- 保留 release ruleset 的 `non_fast_forward` 规则；汇总合并由 App workflow 在检查成功后执行，不依赖仓库 auto-merge 设置。

## 验证

- `make test-release-orchestrator`：通过。
- `actionlint .github/workflows/*.yml`：通过。
- `bash -n scripts/release_orchestrator.sh scripts/test_release_orchestrator.sh`：通过。
- `make release-check COMPOSE_ENV=.env.example`：通过；完整 Scaffold Matrix 通过，profile 启动健康检查因未设置 `JIMU_PROFILES_SMOKE=1` 而跳过。
- `make check-skills`、`make check-capabilities`、`make profiles-check`：通过。
- `git diff --check`：通过。

## 说明

- 首次启用需要安装具有 `contents: write`、`pull_requests: write`、`checks: read`、`issues: write`、`metadata: read` 权限的 GitHub App 并设置 `JIMU_RELEASE_APP_ID`、`JIMU_RELEASE_APP_PRIVATE_KEY`。当前工作分支尚未推送，远端 Actions/App 集成演练未执行；因此不宣称真实 GitHub 自动化已完成验收。
