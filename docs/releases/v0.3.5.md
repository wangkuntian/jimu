# v0.3.5

## 亮点

- PR 关键检查（`CI (PR)`）不再把同一套测试跑两遍：分片在 `go test -race -covermode=atomic` 下一次产出竞态结果与覆盖率 profile。旧设计 `CI (Go)` 实测 **374s（6m15s，热缓存）**（其中 race 长杆 331s、`Test` 276s 并行）。新设计的实测数字**分两个阶段**，它们来自不同配置、**不可混读**：

  | 阶段 | 新 commit（分片冷缓存） | 同一 sha 重跑（缓存命中） | 出处 |
  |---|---:|---:|---|
  | **缓存预热修复前** | 411s | 355s | run `38028086419`（@ `f3bad42`） |
  | **缓存预热修复后**（Task 12） | 376s | **317s** | run `38029714626`（@ `b7f8319`） |

  修复后的代码域收益可归因：**Go 域关键路径 t+372s → t+265s（−29%）**，13 个分片的步骤合计 **2524s → 948s（−62%）**（`Cache Warmup` 把完整构建快照写成 `shards` 风味的唯一保存者，重跑中 13 片与预热自身全部精确命中，预热自身编译步骤降到 2s）。
- **墙钟仍未达到 spec 设定的 ≤4m00s，这里如实说明**：整条 workflow 的墙钟仍受 runner 方差（本轮观测 ±40s）与镜像域影响（同一轮 `docker build` 104s → 228s，会成为关键路径）。本轮真正落地并被实测确认的是**代码域关键路径 t+372s → t+265s（−29%）**与**分片编译量 2524s → 948s（−62%）**。
- 修掉分片缓存的根因：13 个分片共用一个滚动缓存键、保存「先到先得」，最先结束的轻分片 `caps-b`（不构建 `tools/**`）抢到保存权，快照不完整 ⇒ 每个新 commit 只有 1/13 分片命中。步骤级证据：`caps-b` 178s（热 7s）、`core` 238s（热 88s）。新增 `Cache Warmup` job 作为该缓存风味的唯一保存者后，13 个分片 + 预热 job **全部精确命中** 704MB 完整快照（预热 job 自身编译步骤 2s）。
- 覆盖率口径不变：全仓 race + cover **合并覆盖率 70.5%**（非竞态基线 71.1%，阈值 70%），13 个分片、合并 profile 12821 行。余量只有 **+0.5pp，不得据此下调阈值**。
- CI 收敛：**PR 路径**的 3 个 workflow（`ci.yml` + `ci-commit.yml` + `ci-docker.yml`）合并为 1 个（`ci.yml`），加上保留的 `ci-scaffold.yml` 与 `release.yml` 共 3 个；路径过滤器 3 → 1；required checks 21 → 3 个稳定聚合检查。
- 依赖更新全程自动：dependabot → 常驻分支 `dependency-updates`（minor/patch 自动合并）→ 一键开版时随发布分支进入 master。

## 新增

- `.github/actions/go-setup` composite action：Go 版本与滚动构建缓存策略集中一处（`lint`/`shards`/`gates` 三种缓存风味；`ci-scaffold.yml` 因使用独立缓存目录仍保留自带 `GO_VERSION`）。
- `Cache Warmup` job：只编译不执行（`go test -race -covermode=atomic -run='^$' ./...`），与分片并行，是 `shards` 缓存风味的**唯一保存者**。
- 三个稳定聚合检查 `PR Gate`、`Image Gate`、`Scaffold Gate`（`Scaffold Gate` 由原 `Scaffold Matrix` 更名而来）；门禁判定逻辑抽成 `scripts/check_ci_gate.sh`，两个门禁共用一份实现。
- 依赖自动化：常驻分支 `dependency-updates` + `dependabot-auto-merge.yml`（仅 minor/patch，白名单判定）、`sync-dependency-branch.yml`（master → `dependency-updates`，冲突不兜底）、`start-release.yml`（一键开版，手动输入版本号）。

## 变更

- `ci.yml` 成为唯一 PR pipeline（合并 `ci-commit.yml` 与 `ci-docker.yml`）；可分片的竞态与覆盖率由 `scripts/test_shards.sh` 一次产出，覆盖率由分片 profile 合并后复用 `make test-coverage-check` 判定。
- `scripts/race_shards.sh` 更名 `scripts/test_shards.sh`，新增 `--cover` 与 `merge-cover`；`make smoke-check` 的脚本语法检查同步覆盖它与新门禁脚本（10 个脚本）。
- Go `1.26.6` → `1.26.9`（清掉 8 个标准库可达漏洞）；`go.mod` 的 go 指令同步升到 `1.26.9`（Go 1.21+ 的 go 指令含补丁号、同时是最低工具链要求）。`go mod tidy` 还把 `golang.org/x/mod` 的陈旧 `// indirect` 标记更正为直接依赖（它本就被 `tools/checkcapabilities` 直接 import），故直接依赖计数 64 → 65、`docs/profiles/compose-report.md` 的对应基线同步更新。
- **发布物改名并对 `minimal` 增发**：由 4 个 `jimu-<os>-<arch>`（仅 `full`）改为 8 个 `jimu-<profile>-<os>-<arch>`（`full` + `minimal` × 4 平台：linux/darwin × amd64/arm64）。**旧名不再产出**，写死旧名下载的脚本需同步修改。
- `release.yml` 改为 `verify → build(矩阵 ×8) → publish` 并行，替代原来的单 job 串行构建。
- dependabot 改为 4 个生态（`gomod` / `github-actions` / `docker` / `docker-compose`）分组 + 排期错峰 + `target-branch: dependency-updates`；`gomod` 家族组不设 `update-types`（同族必须一起动），长尾 minor/patch 走兜底组，major 单独开 PR 留人工。
- master 的 required checks 从 21 个改为 3 个聚合检查，此后调整分片数无需再改 ruleset；release/* 只有 `non_fast_forward` 规则、无 required checks。
- 文档同步：`docs/CONTRIBUTING.md`（分支策略、PR 门禁、发布物、依赖更新流程）、`README.md`、`skills/jimu/references/gates.md` 的触发口径与检查名。

## 修复

- `govulncheck` 剩余 4 项由 `golang.org/x/net v0.60.0` 清掉。
- **镜像扫描 10 个 HIGH 清零**：9 个来自 `github.com/xuri/excelize/v2`（升级到含修复的伪版本 `v2.11.1-0.20261003002531-6258dcebc4e2`，并连带更新 `xuri/efp`、`richardlehane/mscfb` 等间接依赖），1 个来自 x/net ⇒ 顺带解除了 master 的合并阻塞（`Security Scan` 是 required check）。
- **发布产物此前自报版本 `dev`**（`release.yml` 漏传 `-ldflags`，`cmd/server` 的默认值生效），现已注入 `-X main.version=<tag>`。
- 发布构建里的 `profileoverlay` 会因 step 级 `GOOS`/`GOARCH` 被交叉编译后在本机执行（`exec format error`）—— 若不修，打 tag 当天 8 个平台产物里只有 linux/amd64 能构建成功；现改为在 runner 主机上执行生成器。
- 路径过滤器 router 在大 changeset 下保持 fail-closed，避免检查静默跳过。

## 移除

- `ci-commit.yml` 与 `ci-docker.yml`（并入 `ci.yml`）；`Race Detector (<shard>)`、`Test`、`Race plan`、`Govulncheck`、`Compose Config`、`Publish Release` 等 job 名随重构消失。
- 原 `ci-docker.yml` 中仅对 tag 生效的 license report 两步（该 workflow 只被 `pull_request` 触发，属死代码）。

## 说明

- **待跟进**：`excelize` 目前 pin 在**伪版本**上，待上游发布 `v2.11.1` 后切回正式版，并同时清理 `scripts/govulncheck.sh` 里已失效的 `GO-2026-6452` 豁免。
- **待观察**：`Cache Warmup` 每轮为该 `github.sha` 保存一份约 704MB（压缩后）快照，10 GB/仓 的 Actions cache 配额与 LRU 淘汰需要观察。代价还包括 13 个分片各多花约 14s 解压（runner 分钟数 +178s），这是「用缓存 IO 换编译 CPU」的有意取舍。
- **只能在真实 dependabot PR 上验证**：`pull_request_target` 下 token 是否真可写、auto-merge 是否真在 `PR Gate` 绿后才执行。
- **剩余可优化项**（记录为后续工作）：generator 分片每片 7 次 `go test -list` 守卫约 39s；composereport 守卫用非 race 的 `go run`，预热（race 构建）覆盖不到它。
- **判据提醒**：单实例 runner 速度方差可达 ±40s，绝对值判据（如「最长分片步骤 < 150s」）在单次采样上不稳，后续以「分片步骤合计」或分位数为主判据。
