# v0.5.0

> 状态：开发中。本文件随 v0.5.0 实施增量持续更新。

## 亮点

- 建立 Jimu 通用 Go 脚手架的产品契约，并把生成前一致性检查落到 Descriptor 与 manifest。

## 新增

- 新增模板契约 `docs/templates/v1/`，包含支持矩阵与发布阻断预算。
- `contract.Descriptor` 新增 `MigrationSchemaDeps`、`RuntimeServices` 和 `ProtectedHTTPMiddleware` 声明。
- 新增生成器 `preflight`：写目标目录前校验受保护中间件唯一性、迁移 schema 依赖、表所有权、迁移重复与外部服务配置。
- manifest 导出上述预检事实，并记录在生成的 `.jimu/manifest.json` 中。
- 新增零外部依赖的 `basic-api` 生成路径：独立最小工程、示例 `/api/v1/ping`、`/livez`/`/readyz`，不包含能力目录、数据库/Redis 客户端、Compose 或 OpenAPI 资产。
- 新增完整 `auth-api` 单租户模板：用户、JWT 会话、RBAC、MySQL 8.4、Redis 7、8 张业务表、10 个迁移、24 条业务路由，以及项目自带 Compose、迁移、seed 和 verify。
- CLI 新增 `--template=basic-api|auth-api`，无选择器时默认 `basic-api`；manifest 记录模板与 `support` 级别。
- 新增官方模板发布门禁：读取 `budgets.json` 实测全部模板预算，运行 `basic-api` 无容器 smoke，并在独立 Compose 项目和新数据卷上运行 `auth-api` 端到端。
- manifest 升级到 schema v2：记录 template contract 版本、framework 版本/commit/dirty 状态，以及全部生成文件的 SHA-256。

## 变更

- `jimu new` 与 `jimu capability add` 现在拒绝“存在受保护路由但没有 primary/fallback 中间件提供者”的选择。
- `auth` 是 primary 受保护链提供者；`apikey` 是 fallback，只在没有 `auth` 时接管。
- 迁移 schema 依赖的事实源从 catalog 硬编码表迁移到能力 Descriptor；catalog 表改为派生视图。
- 不重新引入 v0.4.0 已移除的受跟踪 `.env.example`；basic-api 的环境变量与配置入口写入生成的 README。
- 框架容器按已解析能力的 `RuntimeServices` 决定是否连接 MySQL/Redis；零服务装配跳过连接、探活和 DB 指标采集。
- `--profile=minimal` 改为映射到 `auth-api` 的弃用兼容别名并打印警告；其他 profile 不作为对外 CLI 入口。
- `--with` 生成物统一标记为 experimental。
- `auth-api` 不再复用 `minimal` 选区；生成树不含 encryption/notification，配置仅保留 HTTP、management、log、db、redis、id、auth。
- `auth-api` 的宿主机端口支持 `AUTH_API_PORT` / `AUTH_API_MANAGEMENT_PORT` 覆盖，`make verify` 自动跟随；Compose 就绪检查改为 `/readyz`。
- framework commit 改为通过 `git rev-parse --verify HEAD^{commit}` 解析，不再直接读取 `.git/HEAD`；普通 clone 和 linked worktree 行为一致，解析失败会在写目标前阻止生成。
- CLI 的构建版本同步到生成 manifest 的 `framework.version`；开发态 manifest 始终标记 `dirty=true`。

## 验证

- `go test ./... -count=1`：通过。
- CLI 选择器测试：默认 `basic-api`、`--with` experimental、legacy `--profile=minimal` 告警映射、内部 profile 拒绝与选择器互斥均通过。
- 官方模板预算：`basic-api` 为 22 文件 / 5 直接依赖 / 12 个闭包文件 / 568 行；`auth-api` 为 49 文件 / 10 直接依赖 / 23 个闭包文件 / 1,850 行；路由、表、迁移、外部服务与资产均在上限内。
- `basic-api` smoke：生成项目 build/vet/test 通过，无容器启动后 `/livez`、`/readyz`、`/api/v1/ping`、统一 404/405 和 SIGTERM 优雅退出通过，冷生成至就绪低于 60 秒预算。
- `auth-api` 端到端：生成项目 test/vet 通过；独立 Compose 项目和随机端口在全新数据卷上连续两次 `make up` + `make verify` 通过；实测 10 个迁移、8 张业务表、2 个用户和 1 个管理员，密码只在首次 `make up` 输出；缺 MySQL/Redis 均快速失败，`make down` 正常。
- Provenance：普通 clone 与 linked worktree 的 commit 与 Git 实测一致；生成 manifest 的 `generated_file_sha256` 和实际文件逐项匹配，tidy/自检后的 `go.mod`/`go.sum`、合并后的配置均在哈希覆盖范围内。
- `go vet ./...`、`make fmt-check`、`make check-log-usage`：通过。
- `make check-capabilities`：7 项检查全部通过。
- `make profiles-check`：5 个 profile 构建与依赖闭包检查通过；启动冒烟因未设置 `JIMU_PROFILES_SMOKE=1` 跳过。
- `make compose-report` + `make compose-report-check`：报告已按本次代码行数变化更新并校验一致。
