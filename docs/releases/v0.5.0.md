# v0.5.0

> 状态：发布候选。产品契约、模板实现、兼容性决策、文档、全量测试和完整发布门禁已完成；正式发布仍需 release/* PR 和 master tag。

## 亮点

- **Jimu 正式收敛为通用 Go 后端脚手架**：默认交付零外部依赖的 `basic-api`，并提供经过空库端到端验收的单租户 `auth-api`。
- **模板不再只是文档**：CLI、生成前预检、硬预算、真实 Compose 启动和 provenance 都已成为可执行契约。
- **升级前请先读「变更 › 破坏性变更」**：CLI 选择器、`auth-api` 产品语义和 manifest schema v2 都有不兼容调整。

## 新增

- 新增模板契约 `docs/templates/v1/`：支持矩阵、兼容窗口、发布阻断预算和验收条件均有机器可读事实源。
- 新增零外部依赖的 `basic-api`：生成 22 个文件，包含 HTTP、配置、日志、统一错误、`/livez`、`/readyz`、示例路由和优雅停机。
- 新增单租户 `auth-api`：生成 49 个文件，包含用户、JWT access/refresh、Redis 会话、RBAC、MySQL 8.4、8 张业务表、10 个迁移、24 条业务路由和初始化管理员。
- 新增 `jimu new <dir> --template=basic-api|auth-api`；不传选择器时默认 `basic-api`。
- 新增生成前预检：受保护 HTTP 中间件提供者、迁移 schema 依赖、表所有权、迁移文件和 runtime services 必须自洽，失败发生在写目标目录之前。
- 新增官方模板门禁：实测 `budgets.json` 预算、`basic-api` 无容器 smoke、`auth-api` 全新 Compose 数据卷启动、幂等 seed/verify 和缺失外部服务失败路径。
- 新增 manifest schema v2：记录 template contract 版本、framework 版本/commit/dirty 状态，以及全部生成文件的 SHA-256。
- 新增 `auth-api` 端口覆盖：`AUTH_API_PORT` / `AUTH_API_MANAGEMENT_PORT` 可用于并行验收和避开本机端口冲突，`make verify` 自动跟随。

## 变更

### 破坏性变更

- **CLI 选择器改为模板优先**：`--template`、`--profile`、`--with` 三者互斥；不传选择器时默认 `basic-api`。
- **公开 profile 入口移除**：`full`、`minimal`（除临时兼容别名外）、`saas`、`enterprise`、`machine` 仅用于 Jimu 自身构建；CLI 拒绝这些 profile 生成。
- **`--profile=minimal` 降级为兼容别名**：v0.5.x 映射到 `auth-api` 并打印弃用警告，v0.6.0 移除。不要把该别名当作旧项目无损升级通道。
- **`auth-api` 是单租户模板**：只支持一个部署租户，保留不可操作的默认 tenant carrier；不提供多租户管理 API，也不是 v0.4 多租户应用的就地迁移方案。
- **manifest schema v1 不再兼容**：v0.5.0 的 `capability add`、报告和项目读取只接受 schema v2。v0.4.x 生成的项目必须按新版本重新生成并人工 diff，不能直接继续增量管理。
- **实验能力组合不受兼容承诺**：`--with` 仍可生成，但 manifest 标记为 `experimental`；不承诺组合稳定、预算或升级。

### 其他变更

- `auth` 是 primary 受保护链提供者，`apikey` 是 fallback；v0.5.0 不再接受两者同时作为受保护链提供者。
- 迁移 schema 依赖改为从能力 Descriptor 派生；catalog 不再维护第二份硬编码依赖表。
- 运行时容器根据能力的 `RuntimeServices` 决定是否连接 MySQL/Redis；`basic-api` 启动不会创建数据库或 Redis 客户端。
- framework commit 通过 `git rev-parse --verify HEAD^{commit}` 解析，普通 clone 与 linked worktree 行为一致；`dirty` 反映 framework checkout 状态，`dev` / `*-dev` 始终标记为 dirty。
- 生成 manifest 的文件哈希在 tidy、自检和配置合并后计算；manifest 和可选报告自身不计入哈希表。
- `auth-api` 的 Compose 就绪检查使用 `/readyz`；`make up` 返回时服务已可接收请求。
- 不重新引入 v0.4.0 已移除的受跟踪 `.env.example`；生成项目的配置与环境变量说明保留在项目 README。

## 修复

- 修复生成器直接读取 `.git/HEAD` 在 linked worktree 下写出空 commit 的问题。
- 修复 `basic-api` 空服务装配仍可能执行 DB/Redis 配置校验或连接的问题。
- 修复受保护路由声明与实际中间件提供者不一致时仍可能写出半成品项目的问题。
- 修复生成文件清单没有内容摘要、无法核对模板最终产物的问题。
- 修复 Compose smoke 在套餐 ID 已改为字符串后仍按 JSON number 解析的问题。
- 修复 `--with` 测试未把受保护链 fallback `apikey` 计入装配集的问题。
- 修复 `auth-api` 在 Linux 上以 `0600` bind mount 挂载 secret 时容器用户无法读取的问题；改用 Compose 原生 secrets。

## 移除

- 移除 `full`、`saas`、`enterprise`、`machine` 及已弃用 profile 名称作为公开 `jimu new` 入口。
- 移除 `auth` 与 `apikey` 同时提供受保护链的支持。
- 移除生成 manifest schema v1 的写入和读取支持。

## 说明

### 已锁定兼容决策

- **不增加 schema v1 只读兼容层**：接受 v0.5.0 的 manifest 破坏性切换，schema v1 继续 fail-closed。
- **v0.4.x 只支持重新生成 + 人工迁移**：不提供自动项目升级、manifest 重写或存量数据库模板迁移；不把 `jimu capability add` 当作升级通道。

### 从 v0.4.x 升级

1. 框架自身部署没有新增数据库迁移；升级二进制或 Compose 镜像时沿用既有迁移状态。
2. 需要新项目时使用 `jimu new <dir> --template=basic-api` 或 `--template=auth-api`。
3. v0.4.x 已生成的工程默认按“重新生成到新目录 + 人工 diff + 选择性迁移”升级；不要用 v0.5.0 直接覆盖旧工程。
4. schema v1 manifest 不会被 v0.5.0 读取；当前版本不提供单独迁移或重写 manifest，旧项目只能重新生成并人工 diff。
5. `auth-api` 面向全新空库；已有 v0.4 数据库不能直接套用 10 个模板迁移，需按实际 schema 单独评估。

### 已知限制

- v0.5.0 不提供 `jimu upgrade`；显式三方 diff、备份和 rollback 计划在 v0.6.0。
- `auth-api` 不包含公开注册、MFA/passkey、OAuth、验证码、通知、字段级加密、审计、队列、对象存储、观测栈或多租户管理 API。
- `--profile=minimal` 只保证 v0.5.x 兼容，v0.6.0 删除。
- `auth-api` 的管理员密码在首次 `make up` 时显示一次；后续只能从被 gitignore 的本地 secret 读取，丢失后需按本地恢复流程处理。
