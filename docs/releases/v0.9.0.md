# v0.9.0

> 状态：发布候选（2026-11-06）

## 亮点

- 提供 `make demo` 一条命令启动 full server + `jimu-web`，验证路线 B 的全栈体验。
- `jimu-web` 契约来源升级为结构化 `contracts/jimu.lock.json`，固定到 `v0.8.1` 并校验 tag、commit 与 sha256。

## 新增

- `make demo`：独立 Compose 项目启动 full server、MariaDB、Redis，并启动 Vite。
- `make demo-e2e`：启动 demo 栈并运行真实后端 Playwright 用例，覆盖租户/套餐、角色/用户和账号安全。
- `make clean-room-e2e`：本地构建 Release CLI，在临时目录验证 `basic-api`/`auth-api` 生成、`make up` 和 `make verify`。
- `JIMU_API_PROXY_TARGET`：允许覆盖 Vite 的 `/api` 代理目标。
- `docs/DEMO.md`：demo 前置条件、端口、演示路径、停止与排查说明。
- `docs/experiments/v0.9.0-trial.md`、`v0.9.0-gate.md`：外部试用清单与 8 周 gate 证据台账。

## 变更

- `jimu-web` 的契约 pin 从裸 `backend-commit.txt` 升级为 `contracts/jimu.lock.json`。
- demo 使用 18080/19090/23306/26379 等独立端口，避免污染常规开发栈。
- 升级 `github.com/andybalholm/brotli` 到 v1.2.7、`github.com/klauspost/compress` 到 v1.20.2，修复 `GO-2026-6888` 与 `GO-2026-6865`。

## 验证

- 2026-11-05 在 macOS + OrbStack 上实际运行 `make demo`：full server、MariaDB、Redis 和 Vite 全部启动。
- 管理端 `/readyz` 返回 `{"status":"ready"}`，UI 返回 200，经 Vite 代理调用 `POST /api/v1/auth/login` 使用 admin 登录成功。
- Ctrl-C 后 Vite 退出，`make down` 移除 demo 容器和网络；数据卷保留，未影响本机既有 Compose 栈。
- `make demo-e2e` 连续运行两次通过：3 条真实后端用例（注册/零角色、租户/套餐、demo 全链路）约 11s 完成。
- demo 全链路用例创建的角色、用户和租户通过 API 清理，重复运行不依赖手工清库。
- 2026-11-06 本地运行 `make clean-room-e2e`：`basic-api` 生成、`check`、`upgrade --check` 通过；`auth-api` 在全新数据卷上 `make up` / `make verify` 通过，输出 `PASS: clean-room basic-api and auth-api`。
- 2026-11-06 `make release-check-fast` 通过（不含完整脚手架矩阵，完整矩阵由 `Scaffold Gate` 承担）；`govulncheck` 报告 0 个可达漏洞。
- `bash -n scripts/demo.sh` 通过。

## 说明

- demo 使用 `full` profile 和当前 `jimu-web`，不是 `jimu new` 生成的 full-stack 项目，也不是生产采用证据。
- 账号安全页面是占位页；E2E 只验证路由可达和占位状态，不证明 MFA/Passkey 已实现。
- 首次运行需要构建镜像和安装前端依赖；后续运行依赖缓存。
