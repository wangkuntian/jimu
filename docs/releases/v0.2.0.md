# v0.2.0

> 状态：未发布 — 正在 `release/v0.2.0` 集成，本文件随变更持续更新，发布时移除本说明并补充发布日期与验证结果。

## 亮点

多租户回归为正式能力：单归属模型 + JWT 租户上下文 + 全链路行级隔离，并新增可选的开通式注册（注册即开通租户，模板模式初始化权限），替代 v0.1.0 中废弃的伪隔离设计。

## 新增

- **租户体系** — 单归属多租户：`tenants` 表 + 租户 CRUD API，`users`/`roles`/`audit_logs` 携带 `tenant_id` 做行级隔离；租户身份写入 JWT claim（`tid`）经中间件注入请求上下文，不接受客户端 header 传入（旧版基于 header 的伪隔离设计正式废弃）；存量数据迁移归入默认租户（`code=default`）；角色名改为租户内唯一，用户名/邮箱保持全局唯一，登录无需传租户标识
- **开通式注册** — 可选 SaaS 语义（`auth.provisioning.enabled`）：注册即单事务开通新租户，注册者成为 owner，按可配置角色模板自动初始化租户角色与全局权限绑定（模板模式，开关/owner 角色/模板全部可配置）；未启用时注册用户归默认租户
- **Redis 高可用** — `redis.mode` 支持 `single`/`sentinel`/`cluster`，哨兵自动故障转移、集群连接分片；统一客户端接口，session/缓存/队列/限流/分布式锁跨模式复用
- **TOTP 二次验证** — RFC 6238 自研实现；`/auth/mfa/setup|enable|disable` 自助管理，登录可携带 `totp_code`，密钥 AES-GCM 加密落库
- **企业 SSO（通用 OIDC）** — `oauth.providers` 下配置 `issuer_url` 的提供商按通用 OIDC 处理：授权码模式 + discovery（首次拉取后缓存、校验 `issuer` 一致）+ `client_secret_post` 换码 + userinfo 取 `sub`/`email`/`name`，可接入 Keycloak/Okta/Auth0/Azure AD 等；provider 名与回调路径自定义，无需为每个厂商写代码；`Provider.AuthURL` 接口随之改为返回 `(string, error)` 以承载 discovery 失败
- **租户运营（套餐 / 配额 / 用量）** — 新增 `tenant_plans` 表（迁移 014）与 `tenants.plan_id`：套餐定义 `max_users`/`max_roles`/`max_api_keys` 上限（0=不限），`plan_id=0` 表示未分配套餐、不受限（向后兼容）；创建用户（管理端与公开注册）、角色、API Key 前校验配额，超限返回新增错误码 `5005`/403，只拦截新增、不动存量数据；新增 `/api/v1/tenant-plans`（套餐 CRUD，仍被租户使用的套餐不可删除）、`PUT /api/v1/tenants/{id}/plan`（分配/取消套餐）与 `GET /api/v1/tenants/usage`（当前租户用量与上限）；`jimu seed` 内置一个未分配的 `free` 示例套餐
- **gRPC 治理补齐** — 服务端新增 recovery/metrics/timeout 三个一元拦截器：handler panic 转为 `Internal` 并上报错误追踪（此前 panic 会直接终止进程）、新增 `jimu_grpc_server_*` 指标（请求量/错误量/在途/耗时）与 `grpc.timeout_sec` 单请求超时（返回 `DeadlineExceeded`）；出站客户端接入统一熔断器（只把 Unavailable/DeadlineExceeded 计为失败，指标并入 `jimu_breaker_*{component="grpc_client:*"}`）
- **错误追踪上报** — `error_reporting` 配置接入 Sentry；HTTP panic 自动上报（含 trace_id/span_id），优雅停机 Flush
- **OpenObserve 可观测性（默认启用）** — OTLP 统一导出结构化日志/分布式追踪/Prometheus 指标；内置仪表盘随 Git 版本化管理并支持导入/导出同步；MySQL/Redis 采集面板；日志与追踪写入命名流；secret-file 认证
- **OpenObserve 官方 dashboard 模板** — 引入官方（[openobserve/dashboards](https://github.com/openobserve/dashboards)）数据库仪表盘并随监控栈自动同步：`MySQL Metrics Monitoring`（6 面板）、`Redis Metrics Dashboard`（7 面板）默认创建；`PostgreSQL`（opentelemetry-contrib 版，35 面板）作为可选模板按需启用（`dashboards-optional/`，配合 otel-collector 预留的 postgres receiver）；模板的旧版小网格布局已归一到 v8 192 列网格（x/w ×4、y/h ×2 并行列对齐），避免导入后面板缩成一条
- **OpenObserve 默认告警** — 内置 8 条告警规则（错误日志激增 / HTTP 5xx 占比 / DB 连接池饱和 / 队列死信 / Outbox 发布失败 / 依赖熔断打开 / MySQL 线程数 / Redis key 淘汰），`deploy/openobserve/alerts/*.json` 入库并经 v2 告警 API 幂等同步（存在则更新，否则创建）；设置 `ZO_ALERT_WEBHOOK_URL` 后随 `make compose-up` 自动同步（含通知模板与 webhook 目的地），留空跳过
- **结构化日志门禁 logcheck** — `make check-log-usage` 强制检查日志调用规范（消息静态化 + 词汇表字段），CI 已接入
- **debug 模式服务信息** — 根路径暴露版本与环境元数据（`http.mode=debug`）
- **并发上限负载保护** — `server.max_concurrency` / `server.concurrency_wait_ms`：超过并发上限可短排队（默认 0=立即拒绝）后返回 `1010`/503，并输出 `jimu_http_requests_shed_total` 指标，避免过载雪崩
- **缓存进程内防击穿** — `GetOrSet` 在原有 Redis 分布式锁之上增加 singleflight：同一实例内同 key 并发未命中只回源一次，锁被其他实例持有时同样合并（两级防护，锁异常直接回源兜底）
- **PostgreSQL 读写分离** — `db.read_hosts`/`db.read_ports` 从仅 MySQL 扩展到 PostgreSQL（同样 `dbresolver` + `RandomPolicy`），与 MySQL 行为对齐
- **依赖熔断（HTTP 出站/Redis/DB）** — 统一熔断器 `internal/platform/breaker`（连续失败阈值 + 冷却后半开探测）统一接入三类依赖：Redis（命令/连接级 hook）、DB（gorm 语句级回调，读写分离下主库与只读副本一体覆盖）、HTTP 出站 client（原先的私有实现删除，`jimu_httpclient_circuit_*` 指标随之并入 `jimu_breaker_*`）：依赖不可用时快速失败而非每请求等超时；Redis 未命中/业务错误、DB 慢查询超时均不计入失败，避免误熔断；指标 `jimu_breaker_open`/`rejected_total`/`trip_total` 带 `component` 标签（httpclient/redis/db）
- **TLS / mTLS（HTTP + gRPC）** — 新增 `platform/tlsconf` 统一构建 `tls.Config`（最低 TLS 1.2，服务端证书必填）；`client_ca_file` 非空即启用双向认证：HTTP 与 gRPC 均要求并校验客户端证书，gRPC server 由此补齐此前完全缺失的 TLS 支持
- **WebAuthn / 通行密钥** — 新增 `webauthn_credentials` 表（迁移 015）与 `auth.webauthn.*` 配置：已登录用户可注册 Passkey（`/auth/webauthn/register/begin|finish`），并以通行密钥无密码登录（`/auth/webauthn/login/begin|finish`，抗钓鱼强因子，不叠加密码与 TOTP），支持列出/重命名/删除凭证；挑战经 Redis 一次性存储（客户端只持有随机 `session_id`，防挑战替换与重放），注册/登录会话绑定仪式类型与用户，登录后回写签名计数器用于克隆检测，凭证按租户与用户隔离；新增错误码 `2010`（未注册通行密钥）/`2011`（通行密钥校验失败）
- **密码防复用** — 改密（`reset-password`）时拒绝与当前密码或最近 N 个历史密码相同的口令（`auth.password_history_count`，默认 5，0=关闭），命中返回新增错误码 `2008`；历史哈希存于新增表 `password_histories`（迁移 012）并按条数自动裁剪，写入失败不影响改密结果
- **IP 白名单** — `security.ip_allowlist`（公开 API）与 `security.admin_ip_allowlist`（`/api/v1/admin`，先于鉴权生效）支持 CIDR 与单个 IP，启动阶段校验；客户端 IP 依赖 `http.trusted_proxies` 正确配置，否则可被伪造头绕过
- **登录历史** — 新增 `login_histories` 表（迁移 011）记录每次登录尝试：成功/失败/锁定、失败原因、IP、User-Agent，账号不存在时记录用户名；`GET /api/v1/auth/login-history` 自助查询；审计写入失败不影响登录主流程
- **可信设备（记住此设备）** — 登录支持 `remember_device`（仅启用 TOTP 的账号）：成功后返回一次性明文 `device_token`（库中只存 SHA-256 哈希，新增表 `trusted_devices`，迁移 013），后续登录携带 `X-Device-Token` 头且不带 `totp_code` 时跳过 TOTP（密码仍必需）；令牌绑定签发用户、有效期 `auth.trusted_device_days`（默认 30，0=关闭），改密与 `/auth/logout-all` 自动吊销，`GET/DELETE /api/v1/auth/devices` 自助管理，失效记录由保留任务清理
- **泄露口令检查（可选）** — `auth.breach_check_enabled` 开启后注册（含开通式注册）与重置密码校验口令是否出现在 Have I Been Pwned 泄露集合中：k-匿名范围查询只出网 SHA-1 前 5 位并在本地比对，命中返回新增错误码 `2009`；检查服务不可用时放行（只记日志），复用统一出站 client 的超时/重试/熔断
- **请求幂等** — 修复并挂载 `IdempotencyMiddleware`：键绑定「租户 + 用户 + 方法 + 路径」避免跨用户/跨接口命中缓存，新增 `SET NX` 占位（并发同键返回 `409/1009` 而非重复执行）、`Idempotency-Replayed` 标记、5xx 与超大响应释放占位可安全重试；新增 `security.idempotency_enabled`（默认开）与 `security.idempotency_ttl_sec`（默认 24h），挂在认证与租户中间件之后
- **审计日志导出** — 新增 `GET /api/v1/audits/export`：按时间范围（默认最近 7 天，跨度上限 90 天）流式导出当前租户审计日志，`format=csv`（含 UTF-8 BOM）或 `json`（NDJSON），单次上限 5 万条并在导出前校验；CSV 含链式哈希字段，可用于离线校验
- **错误消息多语言补齐** — 每个错误码都补齐中英文文案（此前 `codeToKey` 只覆盖 14 个码，其余错误码会返回「服务器内部错误」，与 403/404 等状态码矛盾）；未登记错误码改为保留调用方消息，并新增测试强制校验 `AllErrorCodes()` 的每个码都有文案
- **CJK 检索回退** — `platform/search` 在查询含中文/日文/韩文时自动改用 LIKE（MySQL）/ILIKE（PostgreSQL）子串匹配，默认分词器下也能命中；LIKE 通配符按字面量转义，标题命中排序优先；代价是不走全文索引，README 说明启用 MySQL ngram / PG zhparser 的方式
- **敏感信息脱敏** — `platform/mask` 提供手机号/邮箱/身份证/银行卡/姓名/IP 脱敏与按字段名判定；日志链路统一接入，凭证整体替换、PII 部分保留，覆盖文件/stdout/OTLP 三类 sink
- **审计防篡改哈希链** — 审计日志按租户链式哈希（`audit.hash_secret` 配置时 HMAC-SHA256，否则 SHA-256）：写入事务内锁定 `audit_chain_head` 保证多实例全序；新增 `GET /api/v1/audits/verify` 校验内容篡改、链接断裂与链尾截断（迁移 010）
- **历史数据保留** — `platform/db` 保留服务按表分批硬删除过期历史数据（审计日志/任务/任务历史/死信/outbox 事件/导入任务），经定时任务调度（`retention.*`，默认关闭）；只清理终态记录，输出 `jimu_retention_deleted_total` 指标
- **全文检索** — `platform/search` 统一检索接口与公共索引表 `search_documents`（迁移 009）：MySQL FULLTEXT 与 PostgreSQL `tsvector` 表达式 GIN 索引两种实现，按租户隔离、幂等覆盖索引；中文分词需数据库侧 ngram/zhparser 扩展
- **时间统一 UTC** — MySQL 连接固定 `loc=UTC` 并显式设置会话 `time_zone='+00:00'`，PostgreSQL 固定 `TimeZone=UTC`：此前 MySQL 只设 `loc=Local` 而会话时区随主机，导致 `DEFAULT CURRENT_TIMESTAMP` 写入与 Go 侧读取可能相差一个时区偏移，现统一为 UTC 存储与读取
- **并发写控制** — `platform/db` 新增 `LockRow`（事务内 `SELECT ... FOR UPDATE` 行锁，SQLite 自动降级）与 `SaveOptimistic`（`version` 列乐观锁，冲突返回 `db.ErrConcurrentUpdate` → 409）；迁移 `008` 为 `users`/`roles`/`tenants` 增加 `version` 列，角色/租户更新改为乐观锁，角色权限替换与用户角色分配在事务内先锁定目标行
- **限流维度扩展** — 新增租户维度（`ratelimit.tenant.*` 全局挂载，平台级视角跳过）与 API Key 维度（`middleware.APIKeyRateLimitMiddleware` 按路由挂载，需前置 `APIKeyAuthMiddleware`）滑动窗口限流；同时修复用户维度限流把 `X-API-Key` 明文写入 Redis key 的问题（改用已认证 Key 的 ID）

## 修复

- 运行时镜像 `apk upgrade` 升级 OpenSSL，修复 Trivy 扫描出的 CVE-2026-14456（HIGH）
- 仪表盘查询字段（OTLP severity）、面板标题初始化、网格填充与坐标轴命名修复
- OTLP 导出补 Basic Auth 认证；OpenObserve 默认凭证改为密码强度合规值
- Prometheus default registerer 类型断言与测试空值守卫
- Compose 持久化数据卷与 Secret 变更后数据库账号密码不一致时的排障与隔离验证流程
- 发布门禁覆盖隔离 Compose 运行时与 API 契约验证
- API Key 补齐租户归属（`api_keys.tenant_id`）：创建时按创建者租户归属，认证后注入租户上下文，列表/详情/撤销按租户隔离，修复机器凭证可越权访问全部租户数据的问题
- 管理端用户导入补齐租户归属：导入用户按操作者所在租户写入 `tenant_id`（无租户上下文归默认租户），修复导入数据 `tenant_id=0` 悬空、按 ID 可被任意租户访问的问题
- 管理端用户接口补齐租户隔离：创建用户按操作者租户归属；详情/更新/禁用/分配角色按租户校验（跨租户按不存在处理）；分配角色只在用户所属租户内解析角色名，修复跨租户读写用户与误绑他租户同名角色的问题
- 任务队列与导入任务补齐租户归属与隔离：`jobs`/`job_history`/`dead_letters`/`import_jobs` 增加 `tenant_id`，任务按提交者租户归属并在消费时恢复该租户到执行上下文；管理端任务/死信/导入任务接口按租户过滤与校验，修复跨租户可见、可重试他租户任务、可读他租户导入任务的问题
- API Key scope 校验接通：新增 `auth.RequireScope` 中间件（空 scopes 拒绝一切、`*` 为全权），挂在 `APIKeyAuthMiddleware` 之后按路由校验能力标签；同时删除与存储格式不一致的死代码 `ScopesString`/`ParseScopes`，修复此前 `scopes` 只存不校验、任何有效 Key 都能访问全部挂载接口的问题
- TOTP 相关错误码映射修复：`2006`（需要提供二次验证码）/`2007`（验证码无效）此前不在 `HTTPStatus` 映射中，落到默认 500，现按未认证返回 401；同时把 `2006`/`2007`/`2008` 补齐到错误码文档列表
- 任务历史按任务 ID 查询补齐租户过滤（`admin/infrastructure` 的 `ListByJobID` 此前不带 `tenant_id` 条件）：有租户上下文时只返回本租户执行历史，平台级视角（tid=0）仍不过滤
- 超时治理闭环：请求超时后若 handler 未产出响应（未写 body 且状态码仍为默认 200）由中间件补 `1008`/504，不再静默挂起；同时把包装了 `context.DeadlineExceeded` 的内部错误统一映射为 `1008`/504，避免超时被误报为 500

- 升级需执行 `jimu migrate` 应用迁移 `005_add_tenants.sql`（mysql/postgres 双份），存量用户/角色自动迁入默认租户
- 迁移 `006_add_api_keys_tenant.sql`（mysql/postgres 双份）为 `api_keys` 增加 `tenant_id`，存量 Key 自动迁入默认租户；API Key 认证后按该租户注入上下文
- 迁移 `012_add_password_histories.sql`（mysql/postgres 双份）新增 `password_histories` 表，用于密码防复用
- 迁移 `013_add_trusted_devices.sql`（mysql/postgres 双份）新增 `trusted_devices` 表，用于「记住此设备」跳过 TOTP；表内只存令牌哈希，`auth.trusted_device_days` 默认 30 天，设为 0 关闭该能力
- 迁移 `014_add_tenant_plans.sql`（mysql/postgres 双份）新增 `tenant_plans` 表并为 `tenants` 增加 `plan_id`（默认 0=未分配，不受配额限制）；存量租户行为不变，需显式分配套餐后才开始校验配额
- 迁移 `015_add_webauthn_credentials.sql`（mysql/postgres 双份）新增 `webauthn_credentials` 表（凭证公钥/签名计数器/备份状态），`auth.webauthn.enabled=false` 时不影响既有登录流程
