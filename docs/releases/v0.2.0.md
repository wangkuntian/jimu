# v0.2.0

> 状态：未发布 — 正在 `release/v0.2.0` 集成，本文件随变更持续更新，发布时移除本说明并补充发布日期与验证结果。

## 亮点

多租户回归为正式能力：单归属模型 + JWT 租户上下文 + 全链路行级隔离，并新增可选的开通式注册（注册即开通租户，模板模式初始化权限），替代 v0.1.0 中废弃的伪隔离设计。

## 新增

- **租户体系** — 单归属多租户：`tenants` 表 + 租户 CRUD API，`users`/`roles`/`audit_logs` 携带 `tenant_id` 做行级隔离；租户身份写入 JWT claim（`tid`）经中间件注入请求上下文，不接受客户端 header 传入（旧版基于 header 的伪隔离设计正式废弃）；存量数据迁移归入默认租户（`code=default`）；角色名改为租户内唯一，用户名/邮箱保持全局唯一，登录无需传租户标识
- **开通式注册** — 可选 SaaS 语义（`auth.provisioning.enabled`）：注册即单事务开通新租户，注册者成为 owner，按可配置角色模板自动初始化租户角色与全局权限绑定（模板模式，开关/owner 角色/模板全部可配置）；未启用时注册用户归默认租户
- **Redis 高可用** — `redis.mode` 支持 `single`/`sentinel`/`cluster`，哨兵自动故障转移、集群连接分片；统一客户端接口，session/缓存/队列/限流/分布式锁跨模式复用
- **TOTP 二次验证** — RFC 6238 自研实现；`/auth/mfa/setup|enable|disable` 自助管理，登录可携带 `totp_code`，密钥 AES-GCM 加密落库
- **统一 gRPC 客户端** — 出站调用封装：连接管理 + 调用超时 + 指数退避重试（幂等安全码）+ panic 恢复拦截器 + Prometheus 指标
- **错误追踪上报** — `error_reporting` 配置接入 Sentry；HTTP panic 自动上报（含 trace_id/span_id），优雅停机 Flush
- **OpenObserve 可观测性（默认启用）** — OTLP 统一导出结构化日志/分布式追踪/Prometheus 指标；内置仪表盘随 Git 版本化管理并支持导入/导出同步；MySQL/Redis 采集面板；日志与追踪写入命名流；secret-file 认证
- **OpenObserve 官方 dashboard 模板** — 引入官方（[openobserve/dashboards](https://github.com/openobserve/dashboards)）数据库仪表盘并随监控栈自动同步：`MySQL Metrics Monitoring`（6 面板）、`Redis Metrics Dashboard`（7 面板）默认创建；`PostgreSQL`（opentelemetry-contrib 版，35 面板）作为可选模板按需启用（`dashboards-optional/`，配合 otel-collector 预留的 postgres receiver）；模板的旧版小网格布局已归一到 v8 192 列网格（x/w ×4、y/h ×2 并行列对齐），避免导入后面板缩成一条
- **OpenObserve 默认告警** — 内置 8 条告警规则（错误日志激增 / HTTP 5xx 占比 / DB 连接池饱和 / 队列死信 / Outbox 发布失败 / 出站熔断打开 / MySQL 线程数 / Redis key 淘汰），`deploy/openobserve/alerts/*.json` 入库并经 v2 告警 API 幂等同步（存在则更新，否则创建）；设置 `ZO_ALERT_WEBHOOK_URL` 后随 `make compose-up` 自动同步（含通知模板与 webhook 目的地），留空跳过
- **结构化日志门禁 logcheck** — `make check-log-usage` 强制检查日志调用规范（消息静态化 + 词汇表字段），CI 已接入
- **debug 模式服务信息** — 根路径暴露版本与环境元数据（`http.mode=debug`）
- **并发上限负载保护** — `server.max_concurrency` / `server.concurrency_wait_ms`：超过并发上限可短排队（默认 0=立即拒绝）后返回 `1010`/503，并输出 `jimu_http_requests_shed_total` 指标，避免过载雪崩
- **缓存进程内防击穿** — `GetOrSet` 在原有 Redis 分布式锁之上增加 singleflight：同一实例内同 key 并发未命中只回源一次，锁被其他实例持有时同样合并（两级防护，锁异常直接回源兜底）
- **PostgreSQL 读写分离** — `db.read_hosts`/`db.read_ports` 从仅 MySQL 扩展到 PostgreSQL（同样 `dbresolver` + `RandomPolicy`），与 MySQL 行为对齐
- **依赖熔断（Redis/DB）** — 新增统一熔断器 `internal/platform/breaker`（连续失败阈值 + 冷却后半开探测）并接入 Redis（命令/连接级 hook）与 DB（语句级 `ConnPool` 包装）：依赖不可用时快速失败而非每请求等超时；Redis 未命中/业务错误、DB 慢查询超时均不计入失败，避免误熔断；指标 `jimu_breaker_open`/`rejected_total`/`trip_total`；DB 在启用读写分离时自动跳过（dbresolver 管理独立连接池，启动日志提示）
- **历史数据保留** — `platform/db` 保留服务按表分批硬删除过期历史数据（审计日志/任务/任务历史/死信/outbox 事件/导入任务），经定时任务调度（`retention.*`，默认关闭）；只清理终态记录，输出 `jimu_retention_deleted_total` 指标
- **全文检索** — `platform/search` 统一检索接口与公共索引表 `search_documents`（迁移 009）：MySQL FULLTEXT 与 PostgreSQL `tsvector` 表达式 GIN 索引两种实现，按租户隔离、幂等覆盖索引；中文分词需数据库侧 ngram/zhparser 扩展
- **连接时区可配置** — 新增 `db.timezone`（IANA 名称，启动校验），MySQL 与 PostgreSQL 连接统一使用；留空保持各驱动原有行为（MySQL `Local`、PG `Asia/Shanghai`）
- **并发写控制** — `platform/db` 新增 `LockRow`（事务内 `SELECT ... FOR UPDATE` 行锁，SQLite 自动降级）与 `SaveOptimistic`（`version` 列乐观锁，冲突返回 `db.ErrConcurrentUpdate` → 409）；迁移 `008` 为 `users`/`roles`/`tenants` 增加 `version` 列，角色/租户更新改为乐观锁，角色权限替换与用户角色分配在事务内先锁定目标行
- **限流维度扩展** — 新增租户维度（`ratelimit.tenant.*` 全局挂载，平台级视角跳过）与 API Key 维度（`middleware.APIKeyRateLimitMiddleware` 按路由挂载，需前置 `APIKeyAuthMiddleware`）滑动窗口限流；同时修复用户维度限流把 `X-API-Key` 明文写入 Redis key 的问题（改用已认证 Key 的 ID）

## 变更

- 可观测性输出端从 Prometheus/Grafana/Loki 自建栈切换为 OpenObserve（OTLP gRPC 推送）
- CI 拆分独立 Docker workflow；commit message 强制全英文（githooks + CI 双重兜底）
- 协作规范整合为单一 AGENTS.md（原分散规范文件收敛）
- 代码库结构分析工具从 graphify 替换为 codebase-memory-mcp
- 通用 Importer 改为通过逐行持久化回调导入；未配置回调时明确报错，避免伪报成功

## 修复

- 运行时镜像 `apk upgrade` 升级 OpenSSL，修复 Trivy 扫描出的 CVE-2026-14456（HIGH）
- 仪表盘查询字段（OTLP severity）、面板标题初始化、网格填充与坐标轴命名修复
- OTLP 导出补 Basic Auth 认证；OpenObserve 默认凭证改为密码强度合规值
- Prometheus default registerer 类型断言与测试空值守卫
- Compose 持久化数据卷与 Secret 变更后数据库账号密码不一致时的排障与隔离验证流程
- 发布门禁覆盖隔离 Compose 运行时与 API 契约验证
- API Key 补齐租户归属（`api_keys.tenant_id`）：创建时按创建者租户归属，认证后注入租户上下文，列表/详情/撤销按租户隔离，修复机器凭证可越权访问全部租户数据的问题
- 管理端用户导入补齐租户归属：导入用户按操作者所在租户写入 `tenant_id`（无租户上下文归默认租户），修复导入数据 `tenant_id=0` 悬空、按 ID 可被任意租户访问的问题
- 管理端用户接口补齐租户隔离：创建用户按操作者租户归属；详情/更新/禁用/分配角色按租户校验（跨租户按不存在处理）；分配角色只在用户所属租户内解析角色名，修复跨租户读写用户与误绑他租户同名角色的问题
- 任务队列与导入任务补齐租户归属与隔离：`jobs`/`job_history`/`dead_letters`/`import_jobs` 增加 `tenant_id`，任务按提交者租户归属并在消费时恢复该租户到执行上下文；管理端任务/死信/导入任务接口按租户过滤与校验，修复跨租户可见、可重试他租户任务、可读他租户导入任务的问题
- API Key scope 校验接通：新增 `auth.RequireScope` 中间件（空 scopes 拒绝一切、`*` 为全权），挂在 `APIKeyAuthMiddleware` 之后按路由校验能力标签；同时删除与存储格式不一致的死代码 `ScopesString`/`ParseScopes`，修复此前 `scopes` 只存不校验、任何有效 Key 都能访问全部挂载接口的问题
- 超时治理闭环：请求超时后若 handler 未产出响应（未写 body 且状态码仍为默认 200）由中间件补 `1008`/504，不再静默挂起；同时把包装了 `context.DeadlineExceeded` 的内部错误统一映射为 `1008`/504，避免超时被误报为 500

## 说明

- 升级需执行 `jimu migrate` 应用迁移 `005_add_tenants.sql`（mysql/postgres 双份），存量用户/角色自动迁入默认租户
- 迁移 `006_add_api_keys_tenant.sql`（mysql/postgres 双份）为 `api_keys` 增加 `tenant_id`，存量 Key 自动迁入默认租户；API Key 认证后按该租户注入上下文
- 迁移 `009_add_search_documents.sql`（mysql/postgres 双份）新增全文检索索引表 `search_documents`；MySQL 使用 FULLTEXT 索引，PostgreSQL 使用 `to_tsvector` 表达式 GIN 索引
- 迁移 `008_add_optimistic_version.sql`（mysql/postgres 双份）为 `users`/`roles`/`tenants` 增加 `version` 列（默认 0），用于乐观锁；并发更新同一行时返回 409，客户端应重新读取后重试
- 迁移 `007_add_task_tenant.sql`（mysql/postgres 双份）为 `jobs`/`job_history`/`dead_letters`/`import_jobs` 增加 `tenant_id`，存量任务自动迁入默认租户；outbox 事件无任务行，其死信租户未知（`0`，按平台级处理）
- 滚动升级窗口内旧 token 无 `tid`，按平台级视角处理（查询不过滤、新建资源归默认租户），刷新 token 后自动收敛
- 开通式注册默认关闭；模板权限依赖 `jimu seed` 写入的全局权限表，缺失条目自动跳过
- Kafka at-least-once 消费端须幂等（同 v0.1.0 说明）
- OpenObserve 默认告警需 `ZO_ALERT_WEBHOOK_URL`（创建告警必须绑定已存在通知目的地）；告警创建要求目标 stream 已有数据，首次启动未就绪的规则稍后重跑 `./deploy/openobserve/sync-alerts.sh` 补齐；告警阈值为保守默认值，按业务调整
