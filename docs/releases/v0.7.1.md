# v0.7.1

> 状态：发布（2026-11-03）

## 亮点

- 两个 certified 模板补齐生产上线检查清单，并提供从生成项目到部署的完整走查。
- 生成模板现在真正执行 CORS 与可信代理配置，并写入基线安全 Header。
- 明确 `v0.5.0` 起的升级支持窗口、五类升级结果处理方式和用户 CI 配方。

## 新增

- `docs/production/basic-api.md`、`docs/production/auth-api.md` 三段式上线检查清单。
- `docs/PRODUCTION.md` 的完整部署走查，覆盖 `basic-api` 和 `auth-api`。
- [ADR 0003](../adr/0003-upgrade-support-window.md)：升级支持窗口与安全修复范围。
- `scripts/security_upgrade_drill.sh`：用 v0.5 旧项目验证安全修复升级链路。
- `jimu upgrade --check` 的 GitHub Actions 和 Makefile 示例。

## 变更

- `basic-api` / `auth-api` 生成模板启用 `http.allowed_origins` 和 `http.trusted_proxies`。
- `http.allowed_origins` 出现 `*` 时，生成项目启动失败。
- 模板写入 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`、CSP 和 HSTS。
- 升级支持窗口固定为 `v0.5.0` 起的 certified 项目；`v0.4.x`/schema v1 重新生成并人工迁移，experimental 不承诺升级兼容。
- 安全修复只保证当前 0.7.x 的最新 patch，旧 patch 不 backport。

## 修复

- 修复生成模板声明了 `http.allowed_origins` / `http.trusted_proxies` 但未实际使用的问题。
- 修复生成模板缺少基线安全 Header 的问题。
- v0.5 认证项目升级到本版本时会安装 5 个安全相关文件；冲突仍按原有三方比较规则保留本地并中止。
