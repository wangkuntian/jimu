# v0.10.0

> 状态：发布候选（2026-11-06）

## 亮点

- 生成器改为**按裁剪生成**：三个预设都从当前主代码仓库按 import 闭包裁剪，不再维护独立的模板树。
- `minimal` 变成真正的零依赖起点：0 能力、最小内核、配置里没有 `db`/`redis` 段。
- `basic-api` 与 `auth-api` 模板退役。

## 新增

- `--template=minimal|auth|full` 三个预设（`jimu new` 默认 `minimal`）。
- `internal/kernel/seedmodel`：种子所需的 5 个纯数据模型从能力 domain 抽出，内核不再 import 任何能力包。
- 内核 `GET /api/v1/ping`（此前是 `basic-api` 模板私有路由）。
- `make check-gate-selectors`：校验 `SCAFFOLD_*_TESTS` 至少匹配一个真实测试。
- `TestMinimalPresetStartsWithoutDependencies`：minimal 在「设置」与「不设置」`ADMIN_PASSWORD` 下都能启动。

## 变更

- `minimal` 的 `configs/app.yaml` 不再含 `db:`/`redis:` 段，`internal/kernel/cache` 与 `internal/e2e` 不再进入产物（296 文件，原 431）。
- `auth` 取代 `auth-api`：`user`/`access`/`auth` + `tenant` 编译闭包，支持级别 `certified`。
- `full` 取代"23 个 `--with`"的拼法：驱动集从 `internal/profiles/full/assembly.go` 派生，支持级别 `validated`。
- 预设项目可以用 `jimu capability add` 继续加能力，不再被 `selection.template != ""` 拒绝。
- `docs/templates/v1/budgets.json` 重建为 minimal/auth/full 三预设预算。

## 不兼容变更

- **模板退役**：`--template=basic-api` 与 `--template=auth-api` 不再被接受。由它们生成的项目执行
  `jimu upgrade` 会直接失败（`ErrRetiredTemplate`）；没有迁移命令，需按新预设重新生成。
- **Compose 不再生成**：新旧预设在生成物里都不含 `docker-compose.yml`。数据库与 Redis 由使用者提供，
  连接信息走 `DB_*` / `REDIS_*` 环境变量。clean-room 门禁改为外部 MySQL/Redis 容器。
- **`/api/v1/ping` 由内核提供**：不再依赖模板私有路由，minimal 也有。
- **`minimal` 不再是"0 能力 + 完整内核"**：现在是"0 能力 + 闭包裁剪内核"。
- **Release 不再发布 server 二进制**：资产只剩 4 个平台的 CLI、`template-bundle.json` 和 checksums。
  Jimu 的交付物是代码；`jimu-web` 用 `make compose-up` 从源码构建后端，不需要预构建二进制。

## 验证

- `go test ./... -count=1`：全仓通过。
- `go test ./tools/generator/ -run TestPresetBudgets`：minimal/auth/full 三份生成树均在预算内。
- `go test ./tools/generator/ -run TestMinimalPresetStartsWithoutDependencies`：两种 env 下 `/livez`、`/readyz`、`/api/v1/ping` 均 200。
- `go run ./tools/checkgateselectors`：三个选择器均非空。
- `bash scripts/test_makefile_contract.sh`：通过（含 release 资产契约）。
- `bash -n scripts/clean_room_e2e.sh`：通过。

## 说明

- `full` 首发是 `validated` 而非 `certified`：预算与构建门禁已就位，但缺完整组合级 E2E。
- 本版本仍未验证外部用户对 `full` 的实际使用；不要把它包装成生产采用证据。
