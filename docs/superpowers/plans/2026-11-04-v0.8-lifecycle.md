# v0.8 生命周期诊断实施计划

> **执行方式：** native 顺序执行；每个 Task 完成验证后提交一次。禁止合并 Task 或额外提交。

**目标：** 完成 P2-02、P3-01、P3-02，提供确定性的只读生命周期诊断、深检和本地 v0.8.0 实验基线。

**架构：** 以现有 upgrade planner 为共享事实源，扩展 `upgrade --json/--diff`，再让 `check` 复用升级状态。fast 检查严格只读；deep 检查只在私有临时副本中运行构建和测试。指标由 Python 标准库脚本本地采集并记录到版本化文档。

**技术栈：** Go 1.26、Cobra、现有 generator/workspace 包、Python 3 标准库。

**需求依据：** `docs/REQUIREMENTS.md` 的 P2-02、P3-01、P3-02。

## 全局约束

- 不采集遥测，不默认上传，不收集业务或真实项目数据。
- 只维护 `basic-api`、`auth-api` 两个 certified 模板；experimental 组合的支持边界不变。
- fast/deep 检查前后，用户项目文件哈希必须完全一致。
- `--json` 与 `--diff` 只允许用于 `upgrade` 的只读模式；conflict 退出语义不变。
- JSON 不含时间戳，条目和诊断稳定排序。
- deep 只串行执行配置校验、`go build ./...`、`go test ./...`，不运行 Make 或业务脚本。
- 不运行未经请求的发布上传、自动合并或 force 操作。

## Review Focus

- conflict 没有 baseline 正文，只能比较 local 与 target；JSON 必须明确说明。
- 二进制或非法 UTF-8 文件不得输出文本 patch，只输出存在状态、哈希和分类。
- `--json --diff` 的机器输出和人类输出必须来自同一 upgrade plan，并保留 conflict 非零退出。
- deep 检查在成功和失败时都不能改写项目。
- 相同输入重复运行的 check/upgrade 机器输出必须一致，且不得包含绝对项目路径或时间戳。
