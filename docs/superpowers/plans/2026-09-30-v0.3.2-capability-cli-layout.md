# v0.3.2 能力命令与目录规范实施计划

> **执行方式：** 当前会话 Inline 逐项实施并验证。仓库禁止未经用户明确指令提交或推送；本计划不包含自动 commit 步骤。

**目标：** 用 `jimu capability create <name>` 替换框架仓的 `module create`，并使能力目录规范与现有 `Descriptor`/`Wire` 模型一致。

**实现思路：** 沿用 Cobra 的 `capability` 命令组以及生成器现有的预检、渲染和失败回滚流程。CRUD 骨架补齐自己的 `Wire`；存量能力保留现有文件名，只在有职责时创建分层目录。目录检查接入现有能力门禁。

**技术栈：** Go 1.26、Cobra、`go/parser`、`tools/generator`、`tools/checkcapabilities`、Make。

## 全局约束

- 未经用户明确指令，不提交、推送或创建分支；保留无关的本地改动。
- 不改变 `jimu new` 和 `jimu capability add` 的行为。生成项目不能包含这两条框架侧开发命令。
- `jimu module create` 不留兼容别名；历史 release note 和历史实施计划保留当时的原文。
- 修改源码时同步更新 README、贡献指南、仓库 skill 和 `docs/releases/v0.3.2.md`。
- 先完成聚焦测试，脚手架重型矩阵放在最终集成阶段运行。

## 任务 1：更名框架 CLI 入口

**涉及文件：** `cmd/cli/main.go`、`cmd/cli/capability.go`、`cmd/cli/capability_test.go`、`tools/generator/climain.go`、`tools/generator/climain_test.go`。

**接口：** `newCapabilityCmd()` 同时注册现有 `newCapabilityAddCmd()` 与新增的 `newCapabilityCreateCmd()`；后者调用骨架生成器。根命令不再注册 `moduleCmd`。

- [ ] 先增加命令树测试：在临时仓库执行 `capability create`，断言能力目录出现；执行 `module create`，断言返回未知命令错误。保留现有 `capability add` 测试。
- [ ] 执行 `go test ./cmd/cli -run 'TestCapability(Create|Add|Module)' -count=1`；新增入口测试应先失败。
- [ ] 将 `create` 挂入 `newCapabilityCmd()`，删除 `moduleCmd`/`moduleCreateCmd` 声明及注册；不改变 `add` 的参数与行为。
- [ ] 更新 `RenderCLIMain` 的 AST 裁剪：`capability.go` 已被 `kernelExcludes` 排除，所以删除针对旧 `moduleCmd` 的声明扫描，同时继续裁掉 `rootCmd.AddCommand(newCmd)` 和 `rootCmd.AddCommand(capabilityCmd)`。更新生成版 CLI 注释与测试，确认生成项目没有 `capability`/`module` 命令。
- [ ] 执行 `go test ./cmd/cli ./tools/generator -run 'TestCapability|TestRenderCLIMain' -count=1`；预期通过。

## 任务 2：让新骨架成为有效能力

## 任务 3：定义并检查目录契约

**涉及文件：** `tools/checkcapabilities/main.go`、新增 `tools/checkcapabilities/structure.go` 与 `structure_test.go`、`README.md`、`AGENTS.md`、`skills/jimu/SKILL.md`、`skills/jimu/references/capability.md`。

**接口：** `checkCapabilityStructure(root string, names []string) error` 用 `go/parser` 检查每个已声明能力根包：恰好一个包级 `Descriptor` 声明、一个包级 `Wire` 函数，且签名符合装配契约。不要求 `module.go` 或四个可选目录。从 profile registry 的能力描述符汇总待检查名称，避免把框架的 25 个能力硬编码进生成项目。

- [ ] 用临时目录测试缺少 `Descriptor`、缺少 `Wire`、重复声明和错误签名；返回 nil 的 `Wire` 以及没有可选层目录的能力必须通过。
- [ ] 执行 `go test ./tools/checkcapabilities -run TestCapabilityStructure -count=1`；新增测试应先失败。
- [ ] 实现 AST 检查，错误包含能力名和路径；在 `main()` 现有成功输出前调用。暂不调整五条汇总输出，跨能力门禁在配套计划中新增汇总行。
- [ ] 将 README 中“四层和 Module 必选”的绝对规则改成已确认的按职责分层规则，并同步 AGENTS/skill；不改五种 profile 与 catalog 的事实描述。
- [ ] 执行 `go test ./tools/checkcapabilities -count=1` 和 `make check-capabilities`；框架仓与生成项目子集夹具均应通过。
