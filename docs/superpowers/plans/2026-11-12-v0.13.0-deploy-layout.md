# v0.13.0 Deploy Components and Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move deployment assets into one `deploy/` surface, make `--deploy` a composable component set, and keep compose, Dockerfile, Helm, K8s, backup, and observability paths consistent between the framework repository and generated projects.

**Architecture:** `deploy/` is the source of truth: `docker/`, `compose/`, `k8s/`, `helm/`, `observability/`, `backup/`, and `scripts/`. The generator selects components from `Generation.Deploy`, renders compose/Dockerfile templates, and copies only matching K8s/Helm/observability assets. Makefile and scripts always use explicit `-f` paths.

**Tech Stack:** Go 1.26, existing `frameworkmanifest` asset actions, Go templates, Docker Compose, Helm, existing generator transaction.

**Spec:** `docs/superpowers/specs/2026-11-12-minimal-project-slimming-design.md`

## Global Constraints

- Do not commit or push unless the user explicitly asks.
- `minimal` default `deploy=[]`; auth default `deploy=[compose]`; full/`--with` default `deploy=[compose,k8s,helm,observability]`.
- `backup` is derived from MySQL runtime service, not a user-selectable component.
- Docker build context remains the project root; only the Dockerfile path becomes `deploy/docker/Dockerfile`.
- Compose exists only at `deploy/compose/`; no root copies.
- Observability is enabled only by the `observability` component.
- v3 projects keep their old deploy layout during upgrade; the new layout applies to new v4 projects.

## Review Focus

- `--deploy=compose` without MySQL must omit `mariadb`/`jimu-init` and still validate.
- `--deploy=k8s` without compose must still generate a buildable Dockerfile.
- `--deploy=observability` alone must generate shared OpenObserve/OTel assets but no target wiring.
- `make up`, `make down`, and `observability.sh` must all use `deploy/compose/...`.
- `deploy=none` must omit Dockerfile, compose, K8s/Helm, backup scripts, and `image` target.
- `capability add` on `compose,observability` must add MySQL backup assets without deleting user files.

### Task 3: Parse deploy components

**Files:** `tools/generator/frameworkmanifest/deploy.go`, `deploy_test.go`, `export.go`.

**Interfaces:**


Accepted names: `compose`, `k8s`, `helm`, `observability`; aliases `none` and `all`. Return sorted unique components. Reject unknown names, empty items, and `none` combined with others.

- [ ] Write table tests for defaults, `all`, `none`, duplicates, and invalid names.
- [ ] Implement parsing with the defaults: minimal `none`, auth `compose`, full/`--with` `all`.
- [ ] Add `Deploy []string` to `frameworkmanifest.Request` and `generator.NewOptions`.
- [ ] Persist the resolved components in `Generation.Deploy`.
- [ ] Run `go test ./tools/generator/frameworkmanifest -run TestParseDeploy -v`.
