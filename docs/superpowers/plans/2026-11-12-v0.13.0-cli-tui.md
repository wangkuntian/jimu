# v0.13.0 CLI TUI and Direct Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Bubble Tea TUI to the Jimu CLI while preserving every existing direct Cobra command, output stream, and exit code; generated projects opt into the TUI with `--cli=both`.

**Architecture:** Move command bodies into `internal/cli/actions` so Cobra and TUI are thin adapters over the same validation and generator calls. Add `internal/cli/tui` for the framework wizard (new/check/upgrade/add), and a generated `cmd/cli/tui.go` for project commands (config/migrate/seed). Direct mode remains the default for scripts, non-TTY, `--no-tui`, and `JIMU_NO_TUI=1`.

**Tech Stack:** Go 1.26, Cobra, Bubble Tea v1.3.10, Lip Gloss v1.1.0, Bubbles v1.0.0.

**Spec:** `docs/superpowers/specs/2026-11-12-minimal-project-slimming-design.md`

## Global Constraints

- Do not commit or push unless the user explicitly asks.
- Direct command flags, stdout/stderr, and exit codes must not change.
- TUI starts only when stdin/stdout is a TTY and `--no-tui`/`JIMU_NO_TUI=1` is absent.
- `minimal` generated projects default `cli_ui=direct`; auth/full/`--with` default `both`.
- TUI code must not be imported by `cmd/server`.
- `NO_COLOR=1`, `--no-color`, and non-TTY output must contain no ANSI escapes.
- Color must not be the only status signal; use text and shape as well.
- The TUI must call action functions directly, never shell out to itself.

## Review Focus

- `jimu` with no arguments in a pipe: must print help and exit 0, never wait for input.
- `jimu tui` without a TTY: must fail with a clear message, not hang.
- `jimu new` with no directory in a TTY: must open the wizard; with a directory it must stay direct.
- TUI and direct `new` with the same inputs: manifest, generation policy, and validation errors must match.
- `--cli=direct` generated project: no Bubble Tea imports and no TUI dependency in `go.mod`.
- `cmd/server` dependency closure: must not contain any TUI package.
- Red/green color weakness: success/warning/failure must remain distinguishable in monochrome output.

### Task 1: Add the shared action layer

**Files:** `internal/cli/actions/*.go`, `internal/cli/scaffold/*.go`.

**Interfaces:**

```go
type NewInput struct {
	Dir, Module, Profile, With, Shape, DBDriver string
	NoTidy, DryRun, Force, Report bool
	SourceRoot string
}
func RunNew(ctx context.Context, in NewInput) (*generator.Result, error)

type CheckInput struct {
	Dir, SourceRoot string
	Deep bool
}
func RunCheck(ctx context.Context, in CheckInput) (*generator.CheckResult, error)

type UpgradeInput struct {
	Dir, SourceRoot string
	NoTidy bool
	DryRun, Check, IncludeDiff bool
}
func RunUpgrade(ctx context.Context, in UpgradeInput) (*generator.PlanUpgradeResult, *generator.UpgradeApplyResult, error)

type AddInput struct {
	Name, Driver, Dir, Module, SourceRoot string
	Force, DryRun bool
}
func RunAddCapability(ctx context.Context, in AddInput) (*generator.Result, error)
```

- [ ] Move flag-to-option mapping out of Cobra `RunE` bodies into these functions.
- [ ] Keep formatting in `internal/cli/scaffold`; actions return facts, not rendered text.
- [ ] Pass `context.Context` through; use `context.Background()` only at the Cobra boundary.
- [ ] Add parity tests proving existing `new`, `check`, `upgrade`, and `add` tests still pass.
- [ ] Run `go test ./internal/cli/... -count=1`.
