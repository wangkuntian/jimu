# v0.7.0 P0 产品化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 P0-01 ~ P0-04，让用户从 GitHub Release 下载单个 `jimu` CLI 后，在没有 Jimu checkout 的情况下生成、运行、检查和升级项目。

**Architecture:** Release CLI 使用独立 `cmd/jimu` 入口，内嵌根包 `jimuassets` 中的 template bundle；生成器新增显式 source metadata 注入，embedded/external source 都走现有 manifest/render/workspace 管线。Release workflow 发布四个平台的 CLI、`template-bundle.json` 和 SHA-256 校验和；独立 clean-room job 在不 checkout 仓库的全新 Runner 上验证两个官方模板。

**Tech Stack:** Go 1.26、Cobra、`embed.FS`、现有 `tools/generator` manifest/render/workspace 管线、GitHub Actions、Docker Compose。

**Spec:** `docs/superpowers/specs/2026-11-03-v0.7.0-p0-productization-design.md`

## Global Constraints

- **禁止自动 commit/push**：未经用户明确指令，不执行 `git add`、`git commit`、`git push`；每个任务结束只报告 diff 和验证结果。
- 文档正文使用中文，`template bundle`、`Release CLI`、`clean-room` 等关键词保留英文。
- 不新增 certified 模板，不支持 Windows，不承诺完全离线。
- 不改变现有 server 二进制、官方模板预算和 `jimu-web`。
- 生成失败必须在写目标目录前发生；不得用 `SKIP` 掩盖 clean-room 环境缺失。
- 保持现有生成器单元测试和官方 scaffold 门禁绿。

## Review Focus

- **Jimu checkout 之外执行 `jimu new`**：不能调用 `frameworkRoot()` 或 git 成功后才生成。
- **External bundle 版本/摘要不一致**：必须 fail-closed，目标目录不能出现空项目。
- **Bundle 漂移**：未跟踪文件、漏嵌入文件或 release metadata 与 binary 不一致必须在发布前失败。
- **Clean-room 依赖缺失**：Docker/Go/CLI 下载失败必须 `FAIL`，不能 `SKIP`。
- **Auth API 数据卷与端口**：必须使用全新 MySQL/Redis volume 和隔离端口，失败时清理且保留诊断日志。
