# v0.13.0 Runtime Closure and Manifest v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `minimal` generation retain only packages reachable from its runtime roots, while persisting the generation policy in a v4 manifest that remains upgrade-compatible with v2/v3 projects.

**Architecture:** Resolve generation policy once in `frameworkmanifest`, persist it in `.jimu/manifest.json`, and pass it into `workspace.Create`. The workspace renders the candidate tree, runs an internal tidy, computes the runtime package closure with `go list`, prunes unreachable Go packages, optionally prunes tests, then runs the existing build/gate checks before the atomic swap.

**Tech Stack:** Go 1.26, `golang.org/x/tools/go/packages`, existing manifest/render/workspace transaction pipeline, Cobra.

**Spec:** `docs/superpowers/specs/2026-11-12-minimal-project-slimming-design.md`

## Global Constraints

- Do not run `git commit`, `git push`, or create branches unless the user explicitly asks.
- Supported closure platforms are `linux/amd64`, `linux/arm64`, and `darwin/arm64`; Windows is unsupported.
- `minimal` defaults: `tests=selected`, `tools=auto`, `deploy=none`, `cli=minimal`, `cli_ui=direct`.
- `--no-tidy` skips only the final tidy; the internal tidy used to compute closure always runs.
- Runtime closure must never be expanded by the test or asset closure.
- A v2/v3 project upgrade must not lose files or gain `compose`/TUI behavior implicitly.
- No generated file may be published unless the final `go build ./...`, self-check, and manifest rewrite succeed.
- User-visible docs stay in Chinese; generated-code comments follow the existing repository style.

## Review Focus

- A package imported only by a build-tagged file on one supported platform: it must survive the union closure.
- A test-only helper package whose non-test files import a pruned DB package: it must be removed, not silently retained.
- `--no-tidy` on a project that needs closure pruning: the internal tidy must still make `go list` resolvable.
- A v3 `minimal` manifest loaded by `jimu check`/`upgrade`: it must map to `deploy=[]`, `cli=minimal`, `cli_ui=direct`.
- `capability add` on a project with `tools=auto`: it must recompute `tools_resolved` without turning the old resolved list into an explicit user choice.
- A generated package with build tags that is unreachable on every supported platform: it must be removed without breaking `go test ./...`.

- Create: `tools/generator/workspace/closure.go`

**Interfaces:**

```go
type Platform struct {
	GOOS   string
	GOARCH string
}

type ClosureOptions struct {
	Roots     []string
	Module    string
	Platforms []Platform
}

type PackageClosure struct {
	Runtime map[string]bool
	Tests   map[string]bool
}

func ComputePackageClosure(ctx context.Context, dir string, opts ClosureOptions) (PackageClosure, error)
```

`Roots` are package import paths such as `example.com/app/cmd/server`. Return keys are import paths. Only packages under `opts.Module` are retained in the result; stdlib and third-party packages are ignored by the pruner.
