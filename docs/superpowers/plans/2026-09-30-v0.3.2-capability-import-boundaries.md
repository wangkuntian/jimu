# v0.3.2 能力跨边界依赖实施计划

> **执行方式：** 当前会话 Inline 逐任务实施和审查。仓库禁止未经用户明确指令提交或推送。

**目标：** 消除能力之间的直接 Go import，包括能力测试和驱动子包，同时保持配置裁剪、事务原子性、MQ 初始化条件和五个 profile 的依赖闭包。

**架构：** 在 `internal/contract` 增加面向用例的端口和纯数据视图；提供方在 `Wire` 中注册端口，消费方通过 `assembly.Context` 读取。持久化仍由所属能力拥有。全部迁移完成后，把静态 import 门禁接入 `tools/checkcapabilities`。

**技术栈：** Go 1.26、GORM、`go/parser`、现有 `assembly.Context`/`contract`、Make 和当前测试夹具。

## 全局约束

- 以 `docs/superpowers/specs/2026-09-30-v0.3.2-capability-boundaries-design.md` 为已确认设计，不扩展为独立脚手架拆分。
- 未经用户明确指令，不提交、推送或覆盖无关本地改动。
- `internal/capabilities/<A>/` 下任何生产或测试 Go 文件都不得 import `internal/capabilities/<B>`，其中 `A != B`；能力树内唯一组合根例外是 `catalog`。
- `Descriptor.Requires`/`SoftRequires`、未启用配置行为、受保护路由和五个 profile 的依赖闭包保持不变。
- 租户开通和 OAuth 首次登录的跨表写入保持原子；`outbox.publisher=event_bus` 不启动 MQ，MQ 模式仍在驱动或 broker 不可用时 fail-closed。
- 源码改动同步 README、skill 和 `docs/releases/v0.3.2.md`；历史 release note/计划保留当时原文。

## 当前依赖清单

生产代码的 22 组直接依赖为：`auth→encryption/notification/outbox/user`、`breach→auth`、`console→auth/ws`、`grpc→user`、`mfa→auth/user`、`oauth→auth/user`、`outbox→queue`、`passkey→auth/user`、`tenant→access/auth/user`、`uploadsec→storage`、`user→encryption/notification/outbox`。测试文件的跨能力 import 单独清点，最终门禁也覆盖测试文件。

## 任务 6：隔离 outbox 与 queue，同时保持 MQ 延迟启动
