# Feature Specification: Jimu 后端框架能力规格

**Feature Branch**: `001-jimu-framework-spec`

**Created**: 2026-08-12

**Status**: Current（能力契约随代码持续同步，2026-08-20 刷新）

**Input**: User description: "根据已有代码为项目生成 spec 文件"

## User Scenarios & Testing

### User Story 1 - 应用开发者快速搭建带认证的服务 (Priority: P1)

应用开发者拿到 Jimu 后，能在不写业务代码的前提下快速搭建一个具备完整用户体系的 HTTP 服务：注册、登录、角色权限控制、统一响应。这是框架最核心的价值。

**Why this priority**: 认证与用户体系是绝大多数后端服务的起点，也是框架差异化能力最集中的部分。

**Independent Test**: 全新项目克隆仓库 → 配置数据库与缓存 → 执行迁移与种子初始化 → 启动服务 → 用管理员账号登录 → 访问受保护接口返回成功。整个过程不编写一行业务代码。

**Acceptance Scenarios**:

1. **Given** 未登录用户，**When** 调用受保护接口，**Then** 返回未认证错误且统一响应 code 非 0
2. **Given** 已登录管理员，**When** 调用受角色权限约束的接口，**Then** 返回成功
3. **Given** 配置了非法枚举值，**When** 启动服务，**Then** 启动失败并报出明确配置错误

---

### User Story 2 - 平台运维部署与观测服务 (Priority: P2)

运维人员通过容器化或 Kubernetes 部署服务，用健康检查、日志、追踪、指标观测运行状态，并能在保障请求不中断的前提下完成优雅停机。

**Why this priority**: 生产可用性是框架作为"稳定底座"的承诺，直接影响服务可靠性。

**Independent Test**: 用 compose 一键起服务 → 访问存活与就绪检查 → 发送停止信号 → 服务在处理完请求后退出且无数据丢失 → 指标端点返回框架维度指标。

**Acceptance Scenarios**:

1. **Given** 数据库或缓存不可达，**When** 请求就绪检查，**Then** 返回未就绪
2. **Given** 服务运行中，**When** 发送停止信号，**Then** 正在处理的请求完成后服务才退出
3. **Given** 开启追踪，**When** 发起请求，**Then** 访问日志中出现关联 ID，可串联整条链路

---

### User Story 3 - 开发者扩展新业务模块 (Priority: P3)

应用开发者遵循统一模块契约新增业务模块（HTTP 路由、定时任务、事件订阅），通过脚手架生成骨架，全程不改动框架内部。

**Why this priority**: 可组合性是框架的关键扩展能力，决定长期可维护性。

**Independent Test**: 用脚手架生成模块骨架 → 实现模块契约 → 启动应用后模块路由自动注册在统一前缀下 → 调用新路由返回统一响应格式。

**Acceptance Scenarios**:

1. **Given** 新生成的模块骨架，**When** 启动应用，**Then** 模块路由自动注册到统一前缀
2. **Given** 业务逻辑，**When** 访问数据，**Then** 依赖接口而非具体实现，实现可替换

---

### User Story 4 - 按需集成高级能力 (Priority: P4)

应用开发者按需启用 OAuth 第三方登录、图形验证码、国际化、多队列、Outbox 一致性、定时任务、特性开关、通知、文件存储、限流、统一出站 HTTP、批量数据导入等可选能力，全部通过配置开关或标准接口接入。

**Why this priority**: 这些能力增强框架竞争力，但非每个服务必需，因此默认不强制挂载。

**Independent Test**: 在配置中启用第三方登录与图形验证码 → 登录页出现第三方入口与验证码 → 校验失败时提示随请求语言切换。

**Acceptance Scenarios**:

1. **Given** 某 OAuth 提供商已启用，**When** 走第三方登录，**Then** 创建或绑定本地用户并返回认证凭证
2. **Given** 请求声明英文语言，**When** 校验失败，**Then** 返回英文错误消息
3. **Given** 切换队列类型，**When** 投递任务，**Then** 任务经所选中间件投递且调用方代码不变

---

### Edge Cases

- 数据库或缓存启动时不可达：服务是保持存活等待恢复，还是直接退出
- 分布式 ID 工作节点号冲突或配置错误
- 迁移部分成功后的状态恢复与一致性
- 第三方登录回调邮箱与本地已有账号冲突时的绑定或合并策略
- 匿名请求的审计日志如何安全落库（脱敏）
- 队列消费失败的重试边界与消息重复投递语义
- 验证码并发校验与重放防护
- 定时任务在多实例下的重复执行（分布式协调）
- 超大请求体、慢请求、代理头伪造
- 配置变更后是否需要重启才生效
- 批量导入文件非法格式、部分行校验失败与超大批量时的处理与回滚语义

## Requirements

### Functional Requirements

**基础底座**

- **FR-001**: 系统 MUST 提供统一 HTTP 入口，所有接口返回统一响应格式，业务错误通过响应 code 表达，而非依赖状态码
- **FR-002**: 系统 MUST 支持多环境配置与高优先级覆盖（环境变量优先），枚举类配置 MUST 在启动时校验，非法值拒绝启动
- **FR-003**: 系统 MUST 支持从文件注入敏感配置（兼容容器密钥注入），不把密钥写进明文配置
- **FR-004**: 系统 MUST 提供结构化日志，支持格式切换、等级过滤与文件滚动
- **FR-005**: 系统 MUST 提供存活与就绪两类健康检查，就绪检查探测数据库与缓存的可用性
- **FR-006**: 系统 MUST 支持优雅停机，按显式生命周期反向停止各组件，不中断在途请求
- **FR-007**: 系统 MUST 提供全局唯一的分布式 ID 生成，数据表主键由应用生成，多实例部署下不冲突

**用户与认证**

- **FR-008**: 系统 MUST 提供用户注册与登录，凭据错误返回统一业务错误且不可枚举猜测
- **FR-009**: 系统 MUST 提供基于令牌的认证与刷新会话机制，支持登出使会话失效
- **FR-010**: 系统 MUST 提供角色权限访问控制（角色、权限、用户角色绑定、角色权限绑定），接口按权限鉴权
- **FR-011**: 系统 MUST 支持服务间调用的密钥认证，与用户认证独立
- **FR-012**: 系统 MUST 支持多家第三方 OAuth 登录，每家按配置独立启用或关闭
- **FR-013**: 系统 MUST 支持登录/注册图形验证码，一次性校验，可配置开关

**安全与防护**

- **FR-014**: 系统 MUST 提供整体与登录/注册维度的限流：整体限速用令牌桶，登录/注册用固定窗口，用户维度用滑动窗口
- **FR-015**: 系统 MUST 提供 HTTP 安全边界：请求体大小限制、超时、可信代理、跨域策略、安全响应头
- **FR-016**: 系统 MUST 提供可选的跨站请求伪造防护与接口签名校验，服务间调用按需挂载
- **FR-017**: 系统 MUST 记录审计日志，批量写入，匿名或敏感请求安全处理

**数据与存储**

- **FR-018**: 系统 MUST 提供数据库迁移工具（升级/回滚/状态/重做）与种子数据初始化命令；种子命令 MUST 幂等，按唯一键 upsert，可安全重复执行不产生重复记录
- **FR-019**: 系统 MUST 提供统一事务管理封装，保证多步写入一致性
- **FR-020**: 系统 MUST 支持读写分离的数据库访问配置
- **FR-021**: 系统 MUST 提供缓存旁路式缓存抽象与分布式锁，供并发与选主场景使用

**集成与扩展**

- **FR-022**: 系统 MUST 提供可插拔队列抽象，支持在多种队列中间件间切换，调用方代码不变
- **FR-023**: 系统 MUST 提供内存事件总线，支持同步与异步发布订阅
- **FR-024**: 系统 MUST 提供 Outbox 模式，保证事件发布与数据库事务的一致性，并支持经消息中间件跨服务发布
- **FR-025**: 系统 MUST 提供定时任务调度，任务定义可持久化，多实例下不重复执行
- **FR-026**: 系统 MUST 提供运行时特性开关，支持按百分比灰度与白名单放量
- **FR-027**: 系统 MUST 提供统一文件存储抽象，支持本地与多家对象存储切换
- **FR-028**: 系统 MUST 提供统一通知抽象，支持邮件、短信、实时推送、回调多种渠道；回调（Webhook）载荷支持 HMAC-SHA256 签名（配置密钥后自动附加 `X-Jimu-Timestamp` 与 `X-Jimu-Signature` 头，时间戳防重放）
- **FR-029**: 系统 MUST 提供分布式追踪与指标采集的标准接入点，按配置启用，不强制挂载；追踪链路需跨越队列/Outbox 等异步边界（生产者注入 trace 上下文，消费者恢复），指标覆盖 HTTP、队列、Outbox、出站调用与定时任务执行（`jimu_scheduler_*`，含成功/失败计数与耗时分布）等维度
- **FR-030**: 系统 MUST 提供常用业务字段校验规则与按语言切换的错误消息
- **FR-031**: 系统 MUST 提供独立的运维管理入口与能力：系统状态、在线用户、强制下线、错误码文档、限流状态可视化（只读查看某作用域与键的当前计数与剩余窗口，不消费令牌）
- **FR-032**: 系统 MUST 提供脚手架命令，一键生成符合模块契约的业务模块骨架
- **FR-033**: 系统 MUST 提供交互式接口文档
- **FR-034**: 系统 MUST 提供容器化与编排部署清单，以及包含静态检查、依赖漏洞扫描、测试覆盖率（门禁 ≥ 70%）、CHANGELOG 变更检查（PR 未更新 CHANGELOG 时 CI 失败）在内的质量门禁；关键解析逻辑（数据导入、JWT 解析、校验规则、ID 生成）提供模糊测试（fuzz）
- **FR-036**: 系统 MUST 提供统一出站 HTTP 客户端，支持请求超时、失败重试（指数退避，仅网络错误与 5xx 重试）、熔断保护（连续失败自动开启，冷却后探测恢复）、按目标 host 独立限流（令牌桶，配置为 0 时禁用）与分布式追踪上下文注入（`traceparent`），第三方服务调用统一复用（OAuth 提供商、Webhook 回调等）
- **FR-037**: 系统 MUST 提供批量数据导入能力，支持 CSV/Excel 模板、字段校验（必填/唯一/格式）、导入预览与任务化执行；导入结果可追踪，部分行失败可定位到具体行且不阻断其余行成功导入
- **FR-038**: 系统 MUST 提供批量数据导出能力，支持 CSV/Excel 格式输出，缺失字段填充为空值不报错；导出结果可被导入能力（FR-037）回读验证，格式互通
- **FR-039**: 系统 MUST 提供可选的 gRPC server（与 HTTP 双栈并存，配置启用）；内置标准健康检查（`grpc_health_v1`）与反射（grpcurl 可探），业务服务通过统一注册口接入，与 HTTP 侧同一套业务模块
- **FR-040**: 系统 MUST 提供自助密码重置：用户以注册邮箱申请重置，系统通过通知渠道发送一次性验证码，验证通过后允许设置新密码；验证码有有效期、一次性，邮箱不存在时不得暴露用户是否存在，重置成功后强制登出该用户全部会话
- **FR-041**: 系统 MUST 对敏感业务字段（邮箱、手机号）提供字段级加密存储：启用密钥时以认证加密落库并维护确定性盲索引（精确查询与唯一约束用），盲索引不泄露原文；可选字段为空时盲索引不得影响多用户共存；未配置密钥时明文存储且功能等价可用

**非目标（约束）**

- **FR-035**: 系统 MUST NOT 引入多租户概念，数据模型不预留租户字段或中间件

### Key Entities

- **用户（User）**: 系统全局唯一身份，含账号、凭据与状态，与角色多对多；邮箱/手机号为可选敏感字段，加密存储并携带盲索引（精确查询与唯一约束）
- **角色（Role）**: 权限的分组单元，与用户、权限均多对多
- **权限（Permission）**: 最小授权单位，映射到接口或操作
- **API 密钥（APIKey）**: 服务间调用凭证，与用户认证独立
- **审计日志（AuditLog）**: 关键操作留痕，匿名请求需脱敏处理
- **第三方绑定（OAuthBinding）**: 用户与外部身份提供方的映射，支持换绑与解绑
- **Outbox 事件（OutboxEvent）**: 待发布的事件记录，是事务一致性的载体
- **定时任务定义（ScheduledJob）**: 可持久化的调度任务，跨实例去重
- **导入任务（ImportJob）**: 批量数据导入作业

## Success Criteria

### Measurable Outcomes

- **SC-001**: 具备文档化前置条件（运行时与依赖已安装）的开发者，能在 30 分钟内启动一个带完整用户认证的可用服务，无需编写业务代码
- **SC-002**: 新增业务模块从脚手架生成到注册完成，开发者改动仅发生在模块目录内，框架内部文件零改动
- **SC-003**: 任一可选能力（第三方登录、验证码、队列、Outbox、定时任务、特性开关、存储、通知、追踪）均可通过配置独立启用或禁用，互不影响
- **SC-004**: 服务启动时若配置非法或关键依赖不可达，能在明确时间内失败并输出可定位的原因，而非带病运行
- **SC-005**: 优雅停机期间在途请求 100% 完成，无连接中断与数据丢失
- **SC-006**: 未认证访问受保护资源 100% 被拒绝；越权访问受角色约束的资源 100% 被拒绝
- **SC-007**: 框架全量改动通过质量门禁（格式化、静态检查、构建、单元与集成测试、依赖漏洞扫描），无警告与高危漏洞
- **SC-008**: 已注册邮箱的用户可经邮件验证码重置密码；验证码一次性、过期即失效，邮箱不存在与存在时接口响应一致（不可枚举），重置后该用户全部会话 100% 失效
- **SC-009**: 配置加密密钥时，email/phone 落库 100% 为密文（库内无明文），盲索引可精确查询且不泄露原文；两个未填 email 的用户可正常共存（盲索引为空不触发唯一冲突）

## Assumptions

- 本 spec 由现有代码（master 分支当前状态）反推生成，描述的是**现状能力契约**，而非未来目标蓝图
- Jimu 是业务无关的通用后端库，业务规则由使用方应用承载，库不内置具体业务逻辑
- 单租户/单组织部署，用户体系全局唯一，多租户明确为非目标
- 目标使用者是 Go 后端应用开发者与平台运维人员；本 spec 面向"能用框架做到什么"而非内部实现
- 技术上下文默认为 Web 服务（HTTP/REST），不覆盖非 HTTP 服务形态
- 已提供性能基准（`make bench`：分布式 ID 生成、登录、Webhook 发送）与本地压测脚本（`make loadtest`），但未定义目标数值；并发量、响应时间等量化指标不虚构具体数值，如需可后续补充性能章节
- 部分能力（如通知渠道的短信、对象存储的特定厂商适配）的完成度差异需在实现核对时以代码为准
